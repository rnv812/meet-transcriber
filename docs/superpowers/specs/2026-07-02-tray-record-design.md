# Кнопка записи в трее: старт/стоп без Claude

Дата: 2026-07-02. Статус: дизайн согласован с пользователем (трей-иконка,
тултип с длительностью, правый клик -> «Остановить запись»; Claude-сценарии
продолжают работать).

## Задача

Запускать и останавливать запись встречи без Claude: ярлык на рабочем столе
(как у voice-control — там pystray-трей), красная иконка в трее пока идёт
запись, наведение показывает длительность, правый клик -> «Остановить запись».
При этом прежние сценарии («Запусти/Останови запись» через Claude) работают
как раньше, и Claude может остановить запись, запущенную кнопкой.

## Компоненты

### 1. Lock-файл записи (в `recorder.py`, общий для CLI и трея)

`record()` при старте создаёт `recordings/.recording.lock` (путь: `<out_root>/
.recording.lock`) с JSON `{"pid": <pid>, "folder": "<папка записи>"}` и удаляет
его в `finally`. Единый для всех способов запуска:

- **Защита от двойной записи:** lock существует и его pid жив -> `SystemExit`
  с сообщением «Запись уже идёт (папка ...)» (трей показывает это уведомлением
  и выходит). Pid мёртв (упали без finally) -> lock перезаписывается, старт
  продолжается.
- **Стоп для Claude:** сценарий «Останови запись» читает lock, убивает pid
  (безопасно: Ogg финализируется постранично, теряется <=0.5 c) — работает
  независимо от того, кто запись запускал.
- Проверка «pid жив» — без новых зависимостей, через ctypes:
  `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, False, pid)` вернул хэндл ->
  процесс существует (закрыть хэндл через CloseHandle). ВАЖНО: `os.kill(pid, 0)`
  на Windows НЕ проверка живости — это безусловный TerminateProcess (убьёт
  запись!), не использовать.

### 2. Стоп-событие в `record()`

`record(out_root, stop_event: threading.Event | None = None)`: существующий
цикл (`while True: time.sleep(0.5)` + вотчдог дорожек) дополнительно выходит,
когда `stop_event` взведён. Поведение CLI `meet record` (Ctrl+C/kill) не
меняется. Финализация та же — блок `finally` закрывает стримы и writers.

### 3. Трей-приложение `src/meet/tray.py`

- `main()`: запускает `record(out_root, stop_event)` в фоновом потоке, в
  главном — pystray-иконка (красный круг, рисуется Pillow на лету).
- Тултип (`icon.title`) обновляется раз в секунду: «Запись: MM:SS» (после часа
  — «H:MM:SS»), форматирование — существующий `fmt_ts` из `output.py`.
- Меню: единственный пункт «Остановить запись» -> `stop_event.set()`, join
  потока записи (штатная финализация), уведомление `icon.notify` «Сохранено:
  <папка>», выход.
- Ошибка старта записи в потоке (нет устройства, lock занят) -> уведомление
  с текстом ошибки и выход (иконка не должна висеть без записи).
- Папка записей — `recordings` относительно корня проекта. GUI-скрипт
  запускается с рабочей директорией ярлыка; надёжнее не зависеть от неё:
  `out_root` = `recordings` рядом с корнем репозитория, вычисленным от
  `__file__` (`src/meet/tray.py` -> три уровня вверх). CLI `meet record`
  по-прежнему использует cwd (не меняется).

### 4. Точка входа без консоли

`pyproject.toml`: секция `[project.gui-scripts]` -> `meet-tray = "meet.tray:main"`.
`pip install -e .` создаёт `.venv/Scripts/meet-tray.exe`, работающий без
консольного окна (pythonw-режим). Ярлык на рабочем столе указывает на него.

### 5. Зависимости

`pystray` и `Pillow` — в основные зависимости `pyproject.toml` (тот же стек,
что в voice-control, на обеих машинах пользователя проверен).

### 6. Документация

- README: раздел «Кнопка записи» — как создать ярлык (готовая powershell-команда
  создания `.lnk` на рабочем столе), поведение иконки, ноутбук (`git pull` +
  `pip install -e .` + тот же ярлык).
- CLAUDE.md: «Запусти запись» — без изменений (плюс упоминание, что пользователь
  может запускать сам кнопкой); «Останови запись» — сначала штатный путь
  (остановить фоновую задачу), если её нет — прочитать `recordings/.recording.lock`
  и убить pid; в обоих случаях затем проверить непустые `sys.opus`/`mic.opus`.

## Что НЕ делаем

- Хоткей (у voice-control есть, здесь не нужен — встречи начинаются не на бегу).
- Транскрибация из трея — по-прежнему через Claude.
- Пауза/возобновление записи — только старт/стоп.
- Автозапуск при старте системы.

## Обработка ошибок

- Второй запуск трея при идущей записи -> уведомление «Запись уже идёт», выход.
- Устройство записи недоступно -> уведомление с ошибкой, lock снят, выход.
- Убийство процесса записи (кнопкой «снять задачу», kill от Claude) -> запись
  валидна (Ogg), lock остаётся со «мёртвым» pid и перезаписывается следующим
  стартом.

## Тестирование

Юниты (без pystray, без аудио — монкипатчим внутренности `record`):
- `record` с взведённым stop_event завершается и снимает lock;
- lock: создаётся с pid/folder, второй `record` при живом pid падает с
  понятным SystemExit, при мёртвом pid — стартует и перезаписывает;
- форматирование тултипа (MM:SS / H:MM:SS) — если не reuse `fmt_ts`, иначе
  уже покрыто.

Приёмка руками (единственный способ проверить трей): запустить ярлык/exe,
увидеть иконку, навести (длительность тикает), поговорить у микрофона,
правый клик -> «Остановить запись», проверить уведомление и непустые
`sys.opus`/`mic.opus` в папке, транскрибировать её. Отдельно: второй запуск
при идущей записи; остановка «как раньше» через Claude (kill по lock-pid).
