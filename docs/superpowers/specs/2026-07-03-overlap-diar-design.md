# Overlap-aware диаризация + метка «(нахлёст)»

Дата: 2026-07-03. Статус: дизайн согласован с пользователем (вариант Б —
переключение на overlap-aware turns + метка uncertain; флаг отката;
приёмка на нескольких реальных встречах через `meet compare`).

## Задача

П.5 бэклога (`docs/2026-07-01-asr-pipeline-ideas.md`): точнее атрибуция на
перебиваниях. Сейчас `diarize.py` читает из pyannote community-1 упрощённый
`exclusive_speaker_diarization` (≤1 спикер в момент времени): когда Б
вставляет «ага» посреди длинной фразы А, exclusive-нарезка отдаёт кусок
фразы А спикеру Б — фраза рвётся. Полная overlap-aware `speaker_diarization`
считается пайплайном всегда, мы её просто не читаем; там turn А непрерывен,
а turn Б лежит поверх.

Цель: (1) атрибуция по overlap-aware turns — порванные фразы чинятся сами,
(2) слова в зонах нахлёста помечаются в транскрипте «(нахлёст)» — читатель
видит, где атрибуция ненадёжна.

Факты разведки (03.07, pyannote.audio 4.0.4 / pyannote.core 6.0.1):
- `DiarizeOutput.speaker_diarization` — overlap-aware Annotation;
  `exclusive_speaker_diarization` — то же после клампа «≤1 спикер/кадр»;
  `speaker_embeddings` отсортированы по `speaker_diarization.labels()`.
- `Annotation.get_overlap() -> Timeline` — готовые регионы, где звучат
  ≥2 разных спикеров (pyannote/core/annotation.py:635).
- Наш `_to_diarization` уже маппит эмбеддинги на labels полной annotation —
  при переходе turns на неё же метки останутся согласованными.

## Компоненты

### 1. `diarize.py`: источник turns и регионов нахлёста

- `Diarization` получает новое опциональное поле
  `overlaps: list[tuple[float, float]] | None = None` — регионы нахлёста
  (сек), по образцу опционального `embeddings`.
- `_to_diarization(result, exclusive: bool = False)`:
  - turns — из `result.speaker_diarization` (overlap-aware) по умолчанию;
    при `exclusive=True` — из `exclusive_speaker_diarization` (прежнее
    поведение, путь отката). Legacy-фолбэки для результатов-Annotation
    (старые pyannote) сохраняются.
  - overlaps — `annotation.get_overlap()` по той же annotation, из Timeline
    в список `(start, end)`, с фильтром `end - start >= MIN_OVERLAP`.
    `MIN_OVERLAP = 1.0` (сек, константа модуля) — отсев «дребезга» и
    суб-секундных поддакиваний, которые плодили бы ложные пометки.
    (Изначально 0.3; поднято до 1.0 по приёмке 03.07.2026: на встрече
    02.07 порог 0.3 дал 204 блока «(нахлёст)» и дробление 441 -> 729
    блоков, порог 1.0 — 75 пометок и 558 блоков при почти той же
    реальной переатрибуции, 124 -> 114 слов.)
  - При `exclusive=True` overlaps не считаются (None) — поведение полностью
    прежнее.
- `diarize_wav(..., exclusive: bool = False)` пробрасывает флаг.

### 2. `diarize.py`: атрибуция и разбиение

- `_word_speaker` не меняется (max-перекрытие, фолбэк «ближайший turn»):
  на overlap-aware turns то же правило само даёт нужный эффект — слова
  длинной фразы А остаются у А, потому что turn А больше не разрезан.
- Новое: `_word_uncertain(word, overlaps) -> bool` — слово попало в зону
  нахлёста, если интервал `[word.start, word.end]` пересекается хотя бы
  с одним регионом (строгое пересечение, длина > 0).
- `split_by_speaker(segments, turns, overlaps=None)`: прогон режется по
  паре `(speaker, uncertain)` — зона нахлёста становится отдельным блоком.
  `_run_to_segment` проставляет `uncertain` создаваемому Segment.
  `overlaps=None` → все слова уверенные, поведение прежнее.

### 3. `asr.Segment`: флаг

- `Segment` получает поле `uncertain: bool = False`. Все существующие
  места создания Segment не меняются (значение по умолчанию).

### 4. Вывод и слияние: `output.py`, `interleave.py`

- `merge_consecutive`: склейка только при одинаковой паре
  `(speaker, uncertain)` — блок нахлёста не слипается с уверенным соседом.
- `to_markdown`: заголовок блока с флагом — `## 12:34 — Имя (нахлёст)`.
- `interleave.py`: `_cut_segment`/`_words_to_segment` создают новые Segment —
  копировать `uncertain` исходного сегмента в каждую часть.
- Mic-дорожка («Вы») не затрагивается (флаг у неё всегда False).

### 5. CLI и пайплайн: `cli.py`, `transcribe.py`

- `meet transcribe --no-overlap` (по образцу `--no-align`): прежнее
  exclusive-поведение без пометок. Прокидывается
  `transcribe(..., overlap=True)` → `diarize_wav(..., exclusive=not overlap)`.
  Это и путь отката, и способ делать A/B (`meet compare` двух прогонов).
- `_transcribe_single`/`_transcribe_two_track`: передать `diar.overlaps`
  в `split_by_speaker`.
- Матчинг имён/сайдкар не меняются (метки и эмбеддинги уже берутся из
  полной annotation).

### 6. Документация

- CLAUDE.md, сценарий «Транскрибируй»: упомянуть блоки «(нахлёст)» (зона
  перебивания, атрибуция ненадёжна — это норма) и флаг `--no-overlap`.
- README: флаг в списке полезных флагов transcribe.
- `docs/2026-07-01-asr-pipeline-ideas.md`: п.4 и п.5 пометить сделанными
  (п.5 — после приёмки).

## Что НЕ делаем (YAGNI)

- Никакой переатрибуции внутри зоны нахлёста (кому именно из двоих отдать
  слово, ASR всё равно слышит доминирующего) — только честная пометка.
- Не показываем второго спикера в метке («нахлёст с X») — начинаем с
  простой пометки; усложним, если приёмка покажет, что этого мало.
- Не трогаем live-режим (`live.py`) — офлайн-пайплайн только.
- Sortformer и прочее из Тир-3 — вне задачи.

## Тестирование

Юниты (без моделей/GPU; для `_to_diarization` — синтетическая
`pyannote.core.Annotation`, пакет лёгкий и уже установлен):
- `_to_diarization`: overlap-aware по умолчанию (turns перекрываются),
  exclusive по флагу (turns прежние, overlaps=None); фильтр MIN_OVERLAP;
  legacy-фолбэк не сломан.
- `_word_uncertain`: пересечение/непересечение/касание границы.
- `split_by_speaker` с overlaps: сценарий «порванная фраза» (длинный turn А
  + короткий turn Б поверх): слова А остаются у А, зона нахлёста — отдельный
  блок с uncertain=True; overlaps=None — прежнее поведение.
- `merge_consecutive`: uncertain-блок не клеится с уверенным того же спикера.
- `to_markdown`: суффикс « (нахлёст)» в заголовке.
- `interleave`: флаг переживает разрезку.
- CLI: `--no-overlap` доходит до `diarize_wav` (по образцу теста `--no-align`,
  если такой есть; иначе — тест прокидывания в `transcribe`).
