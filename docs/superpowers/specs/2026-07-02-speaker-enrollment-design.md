# Авто-имена спикеров: enrollment голосов + матчинг при транскрибации

Дата: 2026-07-02. Статус: дизайн согласован с пользователем (сессия 02.07),
п.2 бэклога `docs/2026-07-01-asr-pipeline-ideas.md`.

## Задача

Сейчас каждый транскрипт выходит со «Спикер 1/2/3», и пользователь каждый раз
объясняет, кто есть кто («Проставь участников»). Участники встреч — постоянные
коллеги; их голоса можно запомнить один раз и дальше подставлять имена
автоматически.

Ключевое требование пользователя: **весь цикл выполняет Claude сам** — пользователь
не запускает команд и не меняет привычный процесс. Единственное, что он делает, —
как и раньше говорит «Спикер 1 — это Даня» для незнакомых базе голосов.

## Ключевой факт

`pyannote/speaker-diarization-community-1` (установленная версия pyannote 4.x)
возвращает `DiarizeOutput.speaker_embeddings` — по одному эмбеддингу-центроиду
(WeSpeaker ResNet34, вектор float) на спикера, в порядке
`speaker_diarization.labels()`. Сейчас `diarize_wav` их выбрасывает. Эмбеддинги
достаются бесплатно при каждой транскрибации: **новых моделей нет, VRAM не растёт,
повторные прогоны GPU для enrollment не нужны.**

## Что храним: только векторы, не звук

В базе голосов лежат **только эмбеддинги** (вектор ~256 float на образец) — сам
звук не сохраняем. Матчинг сравнивает вектор нового спикера с векторами базы
(косинусная близость), исходное аудио для этого не нужно. В каждом образце
хранится `source` — путь к папке записи, из которой он получен: если когда-нибудь
сменится модель эмбеддингов (векторы разных моделей несравнимы), базу можно
пересобрать из ещё лежащих на диске записей той же командой enroll.

## Архитектура

Три части: сайдкар при транскрибации → команда enrollment → авто-матч.

### 1. Сайдкар эмбеддингов при транскрибации

`transcribe` после диаризации сохраняет рядом с транскриптом сайдкар: для папки
записи — `<ISO-дата>_speakers.json` (рядом с `<ISO-дата>_transcript.md`), для
одиночного файла — `<имя>_speakers.json`:

```json
{
  "model": "pyannote/speaker-diarization-community-1",
  "speakers": [
    {"label": "SPEAKER_00", "display": "Спикер 1", "embedding": [0.01, ...]},
    {"label": "SPEAKER_01", "display": "Демьян Петров", "embedding": [...]}
  ]
}
```

- `display` — имя, под которым спикер виден в транскрипте: результат той же
  функции `speaker_names()` из `output.py` (порядок первого появления), либо уже
  подставленное из базы имя. Это гарантирует, что «Спикер 1» из транскрипта
  однозначно резолвится в эмбеддинг.
- Сайдкар пишется всегда, даже если все спикеры распознаны, — свежие образцы
  пригодятся для дообучения базы.
- mic-дорожка («Вы») в сайдкар не попадает — она не диаризуется.

### 2. База голосов `voices/`

Папка в корне проекта, **добавляется в `.gitignore`** (приватные данные, как
`recordings/`). Один файл на человека, имя файла = отображаемое имя:
`voices/Демьян Петров.json`:

```json
{
  "samples": [
    {"embedding": [...], "source": "recordings/2026-06-26_14-00", "date": "2026-06-26"}
  ]
}
```

- Образцы накапливаются с разных встреч. Повторный enrollment из той же записи
  **заменяет** образец с тем же `source`, а не дублирует его.
- Матч человека = максимум косинусной близости по его образцам.

### 3. Команда `meet enroll`

```
meet enroll <папка записи или транскрипт> "Спикер 1=Демьян Петров" ["Спикер 3=Пётр" ...]
```

- Находит сайдкар, резолвит «Спикер N» (или сырую метку `SPEAKER_XX`) в эмбеддинг,
  дописывает образец в `voices/<Имя>.json`. Без GPU, мгновенно.
- Неизвестное имя спикера в маппинге → понятная ошибка со списком доступных.
- Сайдкара нет (старая запись) → сообщение «перетранскрибируй запись, сайдкар
  появится».

### 4. Авто-матч при транскрибации

Новый модуль `src/meet/voices.py`:

- `load_voices()` → `{имя: [эмбеддинги]}` из `voices/`;
- `match_speakers(embeddings, voices)` → `{label: имя}` для уверенных совпадений.
  Уверенность: `cos(top1) >= THRESHOLD` **и** отрыв `cos(top1) - cos(top2) >=
  MARGIN` (top2 — лучший образец другого человека; если в базе один человек —
  только порог).
- Стартовые константы `THRESHOLD = 0.5`, `MARGIN = 0.05` — **калибруются на
  реальных данных** до фиксации (см. «Приёмка»). Логика в одном месте, менять
  дёшево.

Встраивание в `transcribe.py`: `diarize_wav` возвращает dataclass
`Diarization(turns, embeddings)` вместо голого списка (embeddings может быть
None — у pyannote есть краевой путь без центроидов). Совпавшие метки
`SPEAKER_XX` заменяются именами прямо в turns до `split_by_speaker`; несовпавшие
идут как сейчас и получают «Спикер N» в выводе. Сигнатура `split_by_speaker`
не меняется (существующие тесты не трогаются). Два уверенных кластера, совпавших
с одним человеком, получают одно имя — это чинит случай, когда диаризация
разорвала одного говорящего на два кластера.

Консольный лог прозрачности на каждый прогон:

```
голоса: SPEAKER_00 → Демьян Петров (cos 0.72)
голоса: SPEAKER_02 → не распознан (лучший кандидат: Пётр, cos 0.41 < 0.5)
```

### 5. Сценарии CLAUDE.md

- **«Транскрибируй»**: упомянуть авто-имена и сайдкар (что появился рядом файл —
  норма).
- **«Проставь участников»**: после замены имён в транскрипте — вызвать
  `meet enroll` с тем же соответствием (если сайдкар есть). Так база наполняется
  сама по ходу привычной работы, без нового шага для пользователя.

## Обработка ошибок

- `voices/` нет или пуст → транскрибация работает ровно как сейчас.
- pyannote не вернул эмбеддинги → предупреждение в консоль, матчинг и сайдкар
  пропускаются, транскрибация не падает (паттерн как у forced alignment).
- Битый JSON в базе/сайдкаре → предупреждение с именем файла, файл пропускается.

## Не входит в задачу

- Живой режим (`meet live`) — имена по базе голосов в дайджесте; отдельная
  доработка, база проектируется совместимой (см. memory
  meet-live-voice-enrollment-followup).
- Mic-резолвер «Вы vs собеседник» (п.3 бэклога).
- Автоматический enrollment без подтверждения пользователя: имена в базу попадают
  только через явное «Проставь участников» / `meet enroll`.

## Тестирование

Юниты (синтетические векторы, без GPU):
- матчер: порог, отрыв top1/top2, пустая база, один человек в базе, два кластера
  → один человек;
- база: round-trip, дедуп по `source`, битый файл;
- сайдкар: запись/чтение, согласованность `display` с `speaker_names()`;
- enroll: парсинг маппинга, ошибки «нет такого спикера»/«нет сайдкара»;
- переименование turns перед `split_by_speaker`.

## Приёмка (калибровка на реальных встречах)

У пользователя есть две записи с одними и теми же коллегами:
`recordings/2026-06-26_14-00/` и `recordings/2026-07-01_15-02/` (имена спикеров
известны). Сценарий:

1. Транскрибировать 26.06 (появится сайдкар) → enroll всех участников.
2. Транскрибировать 01.07 → в транскрипте должны стоять правильные имена.
3. По консольному логу близостей выставить `THRESHOLD`/`MARGIN`: зазор между
   «свой» (тот же человек между встречами) и «чужой» (разные люди) должен
   вмещать порог с запасом. Зафиксировать замеренные значения в комментарии
   рядом с константами.

Дополнительно: существующий тестовый набор (`pytest -q`) остаётся зелёным.
