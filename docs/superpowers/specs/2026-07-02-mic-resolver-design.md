# Mic-резолвер: точное встраивание реплик при перебиваниях

Дата: 2026-07-02. Статус: дизайн согласован с пользователем (вариант А),
п.3 бэклога `docs/2026-07-01-asr-pipeline-ideas.md`.

## Проблема

Две дорожки (sys — собеседники, mic — «Вы») транскрибируются независимо и
сливаются простой сортировкой по времени **начала** сегмента
(`_transcribe_two_track`: `sorted(sys_segs + mic_segs, key=lambda s: s.start)`).
Короткая реплика, вставленная в середину длинной чужой фразы («Готов», «Ну да»,
«Адаптивный?»), встаёт в транскрипте **после всего абзаца**, потому что абзац
начался раньше. Читатель и протокол саммари видят ответ не на то место диалога —
прямая ошибка атрибуции «кто на что согласился».

Замер на встрече 01.07 (`recordings/2026-07-01_15-02/`): из 20 реплик «Вы»
6 (30%) прозвучали за 8-18 секунд до конца блока, после которого стоят.

## Решение (вариант А — симметричный резчик)

Перед слиянием разрезать сегменты каждой дорожки в точках **начала** сегментов
другой дорожки, пословно (таймкоды слов есть: sys — после forced alignment,
mic — от whisper). Затем прежняя сортировка по start. Чистая детерминированная
постобработка: без моделей, без GPU, без новых зависимостей.

Пример: блок Дани 10:04-10:20, реплика «Вы» на 10:12 → блок режется на
[10:04-10:12] и [10:12-10:20], реплика встаёт между ними.

### Почему резать только по началам (не по концам)

Одного разреза в точке начала чужой реплики достаточно для правильного порядка:
`[A до t] [реплика t] [A после t]` — продолжение начинается со слова с
таймкодом ≥ t, то есть позже начала реплики, и сортировка ставит его после неё.
Разрез по концам плодил бы куски без пользы — соседние куски одного спикера без
чужой реплики между ними всё равно склеит `merge_consecutive` в `output.py`
(пауза между кусками = 0 ≤ max_gap).

## Компоненты

### Новый модуль `src/meet/interleave.py`

- `interleave_tracks(a: list[Segment], b: list[Segment]) -> list[Segment]` —
  разрезать сегменты `a` по началам сегментов `b` и наоборот, вернуть общий
  список, отсортированный по ключу `(start, end)`. Единственная публичная
  функция. Тай-брейк по `end` нужен для края «продолжение начинается ровно в
  start реплики»: короткая реплика тогда встаёт раньше длинного продолжения.
- `_cut_segment(seg: Segment, times: list[float]) -> list[Segment]` — разрезать
  один сегмент по точкам из `times`, попадающим строго внутрь `(seg.start,
  seg.end)`. Слова с `word.start < t` уходят в левую часть, остальные — в
  правую; спикер у частей исходный. Часть без слов не создаётся. Сегмент без
  пословных таймкодов (`seg.words` пуст) не режется.

Границы текста частей — по словам, как в существующем `_run_to_segment`
(`diarize.py`): текст части = конкатенация её слов, `start`/`end` — таймкоды
первого/последнего слова части.

### Изменение в `transcribe.py`

В `_transcribe_two_track` строка
`return sorted(sys_segs + mic_segs, key=lambda s: s.start), diar, name_map`
заменяется на `return interleave_tracks(sys_segs, mic_segs), diar, name_map`.
Одиночный файл (`_transcribe_single`) не меняется — там одна дорожка.

## Что НЕ делаем (решения пользователя, 02.07.2026)

- **Перебивания «собеседник × собеседник»** — не этот механизм; это п.5 бэклога
  (overlap-aware диаризация).
- **Чистка «офисной» речи в mic** (микрофон ловит разговоры пользователя не по
  встрече): не в пайплайне. Надёжного акустического критерия «не для встречи»
  нет, легко потерять настоящие реплики; вычищать лишнее по смыслу — задача LLM
  на этапе разбора/саммари готового транскрипта.
- Пометки нахлёстов в тексте — ресёрч 01.07: пользы для саммари нет.

## Обработка ошибок и краёв

- Пустая одна из дорожек → просто сортировка другой (поведение как сейчас).
- Сегмент без слов → не режется, участвует в сортировке как раньше.
- Точка разреза совпадает с границей сегмента или лежит вне его → разреза нет.
- Несколько чужих реплик внутри одного сегмента → несколько разрезов.
- Автоимена спикеров и сайдкар не затрагиваются: резчик работает после
  `split_by_speaker` и до записи markdown, `speaker` частей наследуется.

## Тестирование

Юниты (`tests/test_interleave.py`, синтетические `Segment`/`Word`):
- разрез длинного сегмента одной чужой репликой → порядок [до, реплика, после];
- несколько реплик внутри одного сегмента;
- реплика на границе / вне сегмента → без разреза;
- сегмент без слов → без разреза;
- пустая дорожка → сортировка второй;
- симметрия: длинная mic-фраза, перебитая sys-репликой, тоже режется;
- текст/таймкоды частей соответствуют словам (стыкуется с merge_consecutive:
  куски без чужой реплики между ними склеиваются обратно).
