# A/B-замер расхождений спикеров: `meet compare`

Дата: 2026-07-03. Статус: дизайн согласован с пользователем (вариант А —
подкоманда в репозитории; первый прогон — alignment vs --no-align на записи
2026-07-02_13-59).

## Задача

Инструмент сравнения двух транскриптов одной записи, сделанных разными
вариантами пайплайна (п.4 бэклога `docs/2026-07-01-asr-pipeline-ideas.md`).
Отвечает на вопрос «что изменилось в атрибуции спикеров и где переслушивать»,
не переслушивая встречу целиком. Нужен как измеритель перед п.5
(overlap-aware диаризация) и для любых будущих правок пайплайна.

Идея повторяет ручной эксперимент с forced alignment (01.07.2026): тексты двух
вариантов почти совпадают (ASR тот же), различается разбиение по спикерам —
значит, можно выровнять тексты пословно и посчитать слова, сменившие спикера.

## Интерфейс

    meet compare A.md B.md

Оба аргумента — транскрипты текущего формата (`## ВРЕМЯ — Спикер`,
см. `output.py: to_markdown`). Старый формат (`**[HH:MM:SS] Спикер N:**`
в recordings/test/) не поддерживаем — при необходимости старые записи
перегоняются текущим пайплайном.

## Компоненты

### 1. Парсер транскрипта (`src/meet/compare.py`)

- Вход — текст md-файла. Frontmatter (`--- ... ---` в начале) и заголовок
  `# ...` пропускаются.
- Блок: строка `## <время> — <спикер>` (время `MM:SS` или `H:MM:SS`,
  разделитель — em-dash, как пишет `to_markdown`), дальше текст до следующего
  `## ` — текст реплики.
- Результат — список слов, каждое с ссылкой на свой блок (спикер, время
  начала блока в секундах).
- Токенизация: слова = последовательности букв/цифр (`\w+`), приведённые
  к нижнему регистру; пунктуация отбрасывается. Этого достаточно —
  сравниваем атрибуцию, не орфографию.

### 2. Пословное выравнивание

- `difflib.SequenceMatcher` по двум спискам нормализованных слов
  (`autojunk=False` — на длинных встречах частые слова не должны выпадать
  из сопоставления).
- Опкоды `equal` — сопоставленные слова: для каждой пары позиций сравниваем
  спикеров A и B. Совпал — «стабильное» слово, нет — «сменившее спикера».
- Опкоды `replace`/`insert`/`delete` — текст разошёлся (недетерминизм ASR,
  разные склейки). Эти слова в счёт смены спикера не идут, считаются
  отдельно как «несовпавший текст».

### 3. Отчёт (в stdout)

- Итоги: всего слов в A и B; сопоставлено; сменило спикера — число и % от
  сопоставленных; несовпавший текст — число и %.
- Матрица «спикер A x спикер B» по сопоставленным словам (счётчики) — если
  диаризация просто иначе пронумеровала спикеров, это видно сразу, без
  ручного маппинга имён.
- Зоны расхождения: подряд идущие сменившие спикера слова объединяются в
  зону; зоны, разделённые не более чем 5 стабильными словами, склеиваются.
  На зону — строка: время блока A, «спикер A -> спикер B» (набор пар зоны),
  число слов, фрагмент текста (первые ~10 слов из A). Это список «что
  переслушивать».
- IMPORTANT: в консольном выводе только ASCII-пунктуация («->», дефисы,
  обычные кавычки) — не-ASCII символы типа «→»/«—» роняют cp866-консоль
  (грабли приёмки enrollment). Кириллица как таковая в cp866 есть — имена
  спикеров и фрагменты текста печатать можно.

### 4. CLI

- Подкоманда `compare` в `cli.py`: два позиционных аргумента — пути к md.
- Ошибки: файла нет или из файла не распарсился ни один блок — `SystemExit`
  с понятным сообщением («Не транскрипт текущего формата: <путь>»).
- Если сопоставлено меньше половины слов — предупреждение «Похоже, это
  транскрипты разных записей», но отчёт всё равно печатается.

## Что НЕ делаем (YAGNI)

- Поддержку старого формата транскриптов из recordings/test/.
- Ручной маппинг имён (`--map`) — матрица спикеров закрывает ту же
  потребность без флага.
- Экспорт отчёта в файл — вывод в stdout, перенаправляется при желании.
- Метрики с эталонной разметкой (DER и т.п.) — это Тир-3, отдельная работа.

## Тестирование

Юниты (`tests/test_compare.py`, без аудио и моделей):
- парсер: frontmatter+заголовок пропущены, блоки `MM:SS` и `H:MM:SS`,
  многострочный текст блока, «не формат» -> ноль блоков;
- выравнивание: искусственные пары транскриптов — точный счёт стабильных /
  сменивших спикера / несовпавшего текста;
- зоны: склейка зон через ≤5 стабильных слов, разрыв при большем зазоре;
- отчёт: вывод кодируется в cp866 без исключений (регрессия граблей
  enrollment).

## Приёмка (первый прогон)

На записи `recordings/2026-07-02_13-59/` (встреча 02.07 — больше участников
и перебиваний, показательнее для отчёта; транскрипт текущего пайплайна с
alignment уже есть):

1. Отложить текущий транскрипт: скопировать в `2026-07-02_transcript.align.md`.
2. Прогнать `meet transcribe --no-align` по той же папке (перезапишет
   `*_transcript.md` и сайдкар) — результат переименовать в
   `2026-07-02_transcript.noalign.md`.
3. Вернуть align-вариант на место канонического `2026-07-02_transcript.md`
   (сайдкар после шага 2 остаётся от no-align прогона — эмбеддинги те же,
   не критично).
4. `meet compare` по align/noalign — проверить глазами: расхождения на стыках
   реплик (ожидаемый эффект alignment), матрица диагональная (имена спикеров
   совпадают), зоны указывают на осмысленные места.
