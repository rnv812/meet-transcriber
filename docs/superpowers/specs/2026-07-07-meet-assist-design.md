# meet assist — live-ассистент встреч на Claude Agent SDK

Дата: 2026-07-07. Статус: дизайн утверждён, план реализации — отдельным документом.

## Проблема

Текущий режим (`meet live` + скилл `live-meeting` в чате Claude Code) имеет три последовательные задержки: окно накопления/распознавания (~20–25 с), вотчер прироста файла (~1.5 КБ ≈ минуты), фоновый субагент-дайджестер. Главное — дайджест и ответы живут в одном разговорном потоке Claude Code: пока сессия читает транскрипт, спросить ничего нельзя. Плюс неустранимый служебный шум в чате.

## Решение (одобрено)

Отдельный процесс `meet assist` (новая CLI-команда) поверх существующего `LiveEngine`: транскрипт пушится в память (без диска и поллинга), две параллельные сессии Claude Agent SDK (дайджестер + вопрос-ответ), UI — локальная веб-страница. Авторизация — подписка (логин Claude Code CLI), без API-ключей.

```
аудио (WASAPI loopback + mic) → LiveEngine (окна 20 с, faster-whisper резидентно)
        │  как сейчас: live_transcript.md + sys.opus/mic.opus (для офлайн-прохода)
        └→ callback → TranscriptBus (in-memory очередь строк)
                ├→ Дайджестер  — SDK-сессия №1 (тик 60–90 с, адаптивно)
                ├→ Вопрос-ответ — SDK-сессия №2 (по запросу, параллельно)
                └→ SSE → веб-страница (лента транскрипта, дайджест, чат вопросов)
```

## Компоненты

### TranscriptBus

In-memory очередь строк транскрипта (`[HH:MM:SS] Спикер: текст`). Продюсер — `LiveEngine.process_window()` (через callback, без изменения его контракта записи на диск). Потребители: дайджестер (drain по тику), Q&A (хвост с момента прошлого вопроса), SSE-рассылка. Диск остаётся журналом и сырьём офлайн-прохода — никто его не поллит.

### Дайджестер (SDK-вызов по тику)

- **Не долгоживущая сессия, а свежий `query()` на каждый тик** с состоянием на стороне приложения: промпт = «текущий полный дайджест (app-state) + новый текст с прошлого тика → верни обновление». Причины: (а) известный Windows-баг SDK — зависание `ClaudeSDKClient` на инициализации (claude-agent-sdk-python issue #208); (б) официальная рекомендация доки sessions держать результат как состояние приложения вместо накопления истории; (в) контекст ограничен по построению — никакого квадратичного роста и пересадок сессии.
- Кэш промпта всё равно работает: системный промпт + глоссарий + контекст задачи — стабильный префикс, при тике < 5 мин (TTL кэша) он читается по 0.1×.
- Модель Sonnet, **без инструментов**: `disallowed_tools` на весь встроенный набор + `can_use_tool`-колбэк deny-all (страховка от зависания на запросе разрешения в headless-процессе).
- Системный промпт (строка-замена, не пресет claude_code): протокол дайджеста из скилла `live-meeting` (тезисы по пунктам обсуждения, 💡-вопросы/пробелы) + `glossary.txt` + контекст задачи (см. «Контекст из Obsidian»). Держать умеренной длины (Windows-лимит командной строки, issue #501).
- Тик адаптивный: 60–90 с, раньше при большом приросте текста; при тишине тик пропускается (ход не тратится).
- **Дельта-режим:** дайджест — нумерованные тезисы, сгруппированные по секциям-пунктам обсуждения (agenda-aware). На тик модель возвращает только операции «добавить/изменить пункт N» в размеченном формате; пустой ответ («НЕТ_НОВЫХ») допустим и ожидаем. Полный документ собирает код; ответ валидируется парсером — невалидный тик отбрасывается (дайджест не мигает мусором), полный rewrite запрещён промптом (вывод тарифицируется 5×). Подход подтверждён литературой по инкрементальной суммаризации (progressive note-taking, arxiv 2510.06677) — полный re-summarize даёт «дребезг» формулировок от тика к тику.

### Вопрос-ответ (SDK-сессия №2)

- Отдельная сессия с памятью диалога: `query(resume=<последний session_id>)` на каждый вопрос (session_id из `ResultMessage`). Персистентный `ClaudeSDKClient` — опционально, если на этой машине не воспроизводится issue #208; resume-вариант — базовый. Доступ сериализуется `asyncio.Lock`; вопросы не ждут дайджестера и наоборот.
- На каждый вопрос инжектится: текущий полный дайджест + хвост транскрипта с прошлого вопроса.
- При поступлении вопроса движок немедленно вызывает внеочередной `process_window()` — последние секунды речи дотранскрибируются до ответа. Целевая задержка ответа: распознавание хвоста (~2–3 с) + ответ модели (~5–10 с).
- **Инструменты: только чтение** — `Read`, `Grep`, `Glob`. Enforcement — колбэк `can_use_tool`: разрешает эти три инструмента только по путям внутри хранилища Obsidian (см. ниже) и папки текущей записи, всё остальное (Bash/Write/Edit/WebFetch/...) — deny; плюс тот же список в `disallowed_tools`.

### Контекст из Obsidian (двухступенчатый)

Хранилище задач: `<vault>\Work\Claude\` (путь — из конфига; между машинами различается). Структура — по `_conventions.md`: индекс `Claude Docs.md` → хаб `_<slug>.md` → главный документ.

1. **При старте:** пользователь называет задачу/тему встречи (аргумент CLI `--task <slug|текст>` или поле на веб-странице до/в начале встречи). Контекст собирает сам процесс assist обычным чтением файлов (без LLM-инструментов): `Claude Docs.md` → хаб задачи → `## Сейчас`, главный документ (`## Главный документ`) и его `## Открытые вопросы`; выжимка инжектится в системный контекст обеих сессий. Задача не названа — работаем без контекста, поле на странице остаётся доступным.
2. **По ходу встречи:** Q&A-сессия может сама ходить в хранилище своими read-only инструментами (уточнить детали по документам, поднять решение из прошлой встречи).

Правила чтения (зашиты в системный промпт Q&A):
- доступ **только** внутри `Work\Claude\` (enforced также пермишенами SDK, не только промптом);
- навигация по «хребту»: сначала хаб `_<slug>.md`, потом документы; найденное грепом не выдавать за актуальное без сверки с хабом;
- заметки со `status: superseded` — история, не актуальное состояние;
- хранилище только читаем, никогда не пишем.

### Веб-интерфейс

Мини-сервер aiohttp на localhost (порт из конфига), одна HTML-страница без сборки (инлайн CSS/JS):
- слева — дайджест (обновление по SSE);
- справа — чат вопросов (POST /ask, ответы стримятся) + кнопка «Что я пропустил?» (late-join recap — готовый вопрос к Q&A-сессии по дайджесту и хвосту);
- внизу — сворачиваемая живая лента транскрипта;
- поле «задача/контекст встречи» (если не задан при старте);
- статус-баннер (ошибки SDK, rate limit, обрыв аудио-дорожки).
Состояния на клиенте нет — перезагрузка страницы безопасна.

### Лимиты, авторизация, отказоустойчивость

- Авторизация: логин Claude Code CLI (подписка Team). SDK берёт OAuth-креды CLI автоматически; выставленный `ANTHROPIC_API_KEY` перебивает подписку — при старте проверяем и предупреждаем. Проверка авторизации — пробный дешёвый `query` (haiku, max_turns=1) с разбором `AssistantMessage.error == "authentication_failed"`.
- Прикидка расхода: ~40–60 ходов дайджестера/час, с дельта-режимом ≈ $0.7–1/час в эквиваленте Sonnet — фон для лимитов Team.
- SDK-вызовы без CLAUDE.md и лишних тулзов: `setting_sources=[]` явно (дефолт менялся между версиями — не полагаться), `system_prompt`-строка. Явный `cli_path` к `claude.cmd` (Windows, issue #252 — `shutil.which` находит неисполнимый bash-скрипт).
- Ошибки SDK: rate limit и ошибки API приходят не исключениями, а в `AssistantMessage.error` / `ResultMessage.subtype` — разбирать в цикле; `ProcessError`/`CLIConnectionError` → пересоздать вызов/клиент; таймаут каждого вызова — свой `asyncio.wait_for`.
- Ошибка SDK-вызова не валит ни движок, ни сервер: ретрай следующим тиком, баннер на странице. При rate limit дайджестер замедляет тик, вопросы в приоритете.
- Падение/закрытие страницы ни на что не влияет.

### Судьба скилла и офлайн-прохода

Скилл `live-meeting` → тонкая обёртка: запустить `meet assist` фоном (с `--task`, если пользователь назвал), сообщить адрес страницы. Чат Claude Code во время встречи полностью свободен. Финальный проход не меняется: после встречи `meet transcribe <папка>` по opus-дорожкам даёт чистовой транскрипт с диаризацией.

## Вне рамок (осознанно)

- Окно транскрибации остаётся 20 с (`--window` есть). VAD-нарезка по паузам вместо таймера и двухзонный транскрипт committed/tentative (LocalAgreement, ufal/whisper_streaming; WhisperX) — главный анти-галлюцинационный приём по всем изученным проектам, но это отдельный эксперимент после пилота: внутри окна уже работает `vad_filter` faster-whisper.
- Живые имена дальних спикеров по `voices/` — существующий follow-up, сюда не тянем.
- Запись заметок в Obsidian из live-режима — никогда (только чтение).

## Тестирование

- Юнит: TranscriptBus (drain/подписки), сборка дайджеста из дельт, батчер тиков (адаптивность, пропуск тишины), пересадка сессии — SDK замокан.
- Интеграционно: fake-движок, скармливающий готовый транскрипт с ускоренным временем; проверка SSE и /ask.
- Пилот на реальной встрече — критерий приёмки: вопрос → ответ ≤ 15 с; дайджест отстаёт ≤ 2 мин; ноль ручной возни в чате Claude Code.
