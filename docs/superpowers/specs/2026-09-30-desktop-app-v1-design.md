# meet desktop v1 — нативное Windows-приложение: дизайн

Дата: 2026-09-30. Ветка `feat/desktop-app-v1` поверх `feat/desktop-app-architecture`.
Предыстория и общая архитектура — `docs/2026-08-17-desktop-app-architecture-plan.md`
(план ветки, фазы Ф0–Ф5 сделаны, 504 теста зелёные на 30.09.2026). Этот документ
не заменяет план, а фиксирует **объём и решения первой выпускаемой версии**.

## Цель

Устанавливаемое Windows-приложение для записи и расшифровки встреч, которым
пользуются автор и его коллеги без знания Python: скачал установщик, прошёл
мастер, дальше — трей и окно. Немного функций, но удобно и аккуратно.

**Критерии успеха v1**

1. Коллега на чистой Windows 11 ставит приложение из `meet-setup-x.y.z.exe` и
   проходит мастер первого запуска без инструкций в чате.
2. Запись встречи → расшифровка со спикерами → имена людей проставлены в
   карточке записи; на следующей встрече знакомые голоса подписаны сами.
3. Импортированный mp3/mp4 чужой записи расшифровывается так же.
4. Работает на машине с NVIDIA (CUDA) и без неё (CPU, медленнее, с честным
   прогнозом времени).
5. В простое при закрытом окне оболочка + резидент занимают < 100 МБ RAM и ~0% CPU.

**Ограничение по происхождению:** работа ведётся на слияние с репозиторием
автора (`dezlorator1/ai_transcriber`). Сохраняются все инварианты плана ветки:
CLI `meet …`, lock-протокол записи (`.recording.lock`, `tray.lock`, `command`),
публичный маркер `gpu.lock`, сценарии CLAUDE.md, работа из репозитория.

## Объём

**Входит в v1**

- Трей: ЛКМ — открыть окно; ПКМ — меню действий (Открыть, Начать/Остановить
  запись, Импортировать файл…, Автозапись ✓, Выход); иконка отражает состояние.
- Уведомления Windows: начало записи (ручной и авто), запись сохранена,
  расшифровка готова / ошибка.
- Главное окно, три колонки: навигация (Записи, Голоса, Настройки) → список
  записей → карточка записи.
- Импорт аудио/видеофайлов (перетаскивание и диалог).
- Автозапись по звонку (ядро уже есть) — переключатель в меню трея и в настройках.
- Карточка записи: переименование спикеров с записью в базу голосов, текст
  реплик, проигрывание фрагмента по клику на таймкод, экспорт .md/.txt/.srt.
- Раздел «Голоса»: люди с аватарами (инициалы на цвете по умолчанию, своё фото).
- Упрощённые настройки, диагностика.
- Два профиля движка: CUDA и CPU.
- Установщик NSIS, мастер первого запуска, установка движка при первом запуске,
  сборка в GitHub Actions, релизы в GitHub Releases.
- Ассистент (добавлен 30.09.2026, см. раздел «Ассистент»): живой режим (лента,
  дайджест, вопросы) в плавающей панели и в карточке идущей записи; итоги и
  вопросы по готовой встрече; база знаний; сохранение в папку заметок.
  Модель — внешняя: Claude Code или Codex CLI по подписке пользователя, либо
  локальная OpenAI-совместимая.

**Не входит в v1** (остаётся в коде ветки, но скрыто или не делается)

- Полноценный редактор: правка текста, сквозной синхронный плеер с подсветкой.
- Календарь Outlook, пост-хук Claude — остаются в коде, в интерфейсе в
  «Дополнительно».
- Набор готовых иконок-аватаров, автообновление без участия пользователя,
  подпись установщика, whisper.cpp-бэкенд, mac/Linux.

## Архитектура

```
┌ Оболочка Tauri 2 (Rust) ─────────────────────────────────────┐
│ трей + меню · уведомления · главное окно (WebView2, React) · │
│ автозапуск · sidecar-резидент с перезапуском · мастер        │
└──────────── HTTP + SSE, 127.0.0.1, bearer-токен ─────────────┘
┌ Резидент meet (Python) ───────────────────────────────────────┐
│ запись (recorder) · автозапись (watch) · очередь задач       │
│ (подпроцессы transcribe/import/enroll) · библиотека · голоса │
│ · настройки · движок и модели                                 │
└───────────────────────────────────────────────────────────────┘
   Файлы — источник истины: <recordings>/<дата_время>/ , <voices>/
```

- **Один трей — в оболочке Tauri.** Трей pystray (`meet-tray`) остаётся для
  работы без оболочки (CLI/репозиторий), но при запущенной оболочке не
  создаётся: резидент запускается оболочкой в режиме без иконки.
- **Резидент — sidecar оболочки.** Оболочка стартует его при запуске, следит за
  процессом, перезапускает при падении (до 3 раз подряд, затем уведомление
  «Сервис не запускается» со ссылкой на лог). Адрес и токен API — как в ветке,
  `daemon.json`.
- **Главное окно создаётся по требованию и уничтожается при закрытии** (не
  прячется): WebView2 держит 100–200 МБ, в фоне их быть не должно. Трей,
  меню и уведомления живут в Rust-процессе и WebView не требуют.
- **Тяжёлая работа — только в подпроцессах** очереди задач (как в ветке): torch,
  Whisper, pyannote в резидент не импортируются. Подпроцесс запускается с
  приоритетом `BELOW_NORMAL`; по завершении память и VRAM освобождаются.

## Резидент: изменения ядра

1. **Фиксы окружения** (с регрессионными тестами, первые кандидаты в PR автору):
   - `asr._add_nvidia_dll_dirs()` дополнительно добавляет каталоги `nvidia/*/bin`
     в `PATH`: ctranslate2 грузит cuBLAS лениво через `LoadLibrary`, который
     смотрит `PATH`, а не `add_dll_directory`. Без CUDA Toolkit в `PATH`
     расшифровка падает с `cublas64_12.dll is not found`.
   - PyAV: faster-whisper 1.2.1 передаёт `av.open(..., metadata_errors=...)`,
     которого нет в `av` 19.x. Ограничить `av<19` в зависимостях (18.1.0 проверена).
2. **Профиль движка `cuda` / `cpu`** — настройка `asr.device`, автоопределение по
   наличию NVIDIA GPU. `cpu`: `compute_type="int8"`, модель по умолчанию —
   более лёгкая (кандидаты `large-v3-turbo` и `medium`; выбор — замером качества
   и времени на встрече 30.09 в рамках плана), pyannote и выравнивание на CPU.
   Прогноз времени расшифровки = длительность × коэффициент профиля (замеряем).
3. **Импорт файла** — задача очереди `import`: создаёт папку записи
   `<recordings>/<дата_время>_import/`, копирует исходник (оригинал не
   трогается), пишет `meta.json` (`source: "import"`, исходное имя) и ставит
   `transcribe`. Поддерживаемые форматы: mp3, mp4, m4a, wav, ogg, opus, webm,
   mkv (декодирует ffmpeg). API: `POST /recordings/import {path}`.
4. **Голоса и аватары** — API поверх `voices.py`:
   `GET /voices` (имя, число встреч, секунды речи, есть ли фото),
   `GET /voices/{name}/avatar`, `PUT /voices/{name}/avatar` (PNG/JPEG → квадрат
   256×256 PNG рядом с голосом), `DELETE /voices/{name}/avatar`,
   `POST /voices/{name}/rename`, `POST /voices/{a}/merge {into}`,
   `DELETE /voices/{name}`. Цвет аватара-инициалов вычисляется детерминированно
   из имени (одинаков в любом месте UI).
   Для «прослушать образец», числа встреч и секунд речи ничего нового не
   хранится: всё выводится из `transcript.json` **всех записей библиотеки**, а не
   только тех, откуда взяты образцы голоса. Встречи — число записей, где есть
   хотя бы одна реплика со спикером = имя человека; секунды — сумма длительностей
   этих реплик (битые start/end пропускаются); число образцов — по-прежнему из
   базы голосов. Так считается и встреча, где человека узнали автоматически и
   образец из неё не брали. Транскрипт каждой записи разбирается один раз на
   запрос списка. Образец — самая длинная реплика человека в самой свежей (по
   имени папки) записи, где он говорит. Раз имя в транскриптах — источник
   статистики, `rename` и `merge` после переноса файлов голоса переписывают
   `speaker` старое→новое во всех `transcript.json` библиотеки (атомарно);
   `merge` пишет итоговый файл голоса атомарно; смена только регистра имени
   («демьян» → «Демьян», на Windows это тот же файл) разрешена и идёт через
   временное имя. Нет таких реплик (голос взят из файла вне библиотеки, запись
   удалена) — статистика нулевая и образца нет, это не ошибка.
5. **Метаданные записи** — `meta.json`: `title` (переименование записи),
   `source` (`record`/`auto`/`import`). Отсутствующий `meta.json` не ошибка.
6. **Экспорт** — `GET /recordings/{id}/export?format=md|txt|srt`.
7. **Режим без иконки** для резидента (`meet-tray --headless` или эквивалент),
   используемый оболочкой; поведение автозаписи и lock-протокол прежние.

## Оболочка и окно

**Трей.** Иконки состояний: дежурю (серая), пишу (красная точка), расшифровываю
(синее кольцо). Тултип: состояние и длительность записи. ЛКМ и двойной клик —
открыть окно. ПКМ — меню: Открыть · Начать запись / Остановить запись ·
Отменить запись (только во время записи) · Импортировать файл… · Автозапись ✓ ·
Выход. Переключатель автозаписи в меню и в настройках — одна и та же настройка.

**Уведомления Windows:** «Идёт запись» (с пометкой «авто» и программой звонка
при автозаписи); «Запись сохранена — расшифровываю»; «Готово: N спикеров, M
узнаны» (клик открывает запись); «Ошибка расшифровки» (клик — запись с причиной).

**Главное окно** — стиль тёмный, по токенам ветки (`app/src/tokens.css`, язык
Linear, шрифт Onest). Три колонки:

1. Навигация: Записи · Голоса · Настройки. В шапке — индикатор записи
   «● REC 12:34 · Стоп», пока запись идёт.
2. Список записей (раздел «Записи»): зона импорта перетаскиванием сверху, записи
   по дате (название, дата, длительность, число спикеров, статус: пишется /
   в очереди / этап расшифровки с прогрессом / готово / ошибка). Поиск по
   названиям и тексту транскриптов.
3. Карточка записи: название (редактируемое), участники с аватарами, кнопки
   Экспорт · Открыть папку · Перерасшифровать · Удалить; реплики блоками
   «время — спикер — текст». Клик по таймкоду проигрывает запись с этого места
   (встроенный `<audio>`, дорожка отдаётся резидентом с Range). Клик по
   «Спикер N» — поповер «Кто это?»: ввод имени с подсказками из базы, флажок
   «Запомнить голос» (по умолчанию включён) → enroll и замена по всему транскрипту.
   Пометка «(нахлёст)» у блоков нахлёста сохраняется.

**Раздел «Голоса»:** сетка людей (аватар, имя, число встреч, минуты речи).
Карточка человека: имя (переименовать), аватар (загрузить файл / вставить из
буфера / сбросить к инициалам; обрезка в круг), «Прослушать образец» (фрагмент
из последней встречи), список встреч, «Объединить с…», «Удалить голос».

**Настройки:** Запись и устройства · Автозапись (программы звонков, задержка
остановки, минимальная длина) · Распознавание (профиль cuda/cpu, модель, язык,
термины `hotwords` с счётчиком лимита) · Движок и модели · Диагностика ·
О программе (версия, ссылка на Releases) · Дополнительно (свёрнуто: LLM,
заметки, хук — как в ветке).

## Установка и первый запуск

**Установщик** — NSIS из `tauri build`, ~60–80 МБ: оболочка, код резидента,
`uv.exe`, `ffmpeg` (LGPL-сборка). Ставится в профиль пользователя без прав
администратора, добавляет автозапуск.

**Движок** ставится при первом запуске в `%LOCALAPPDATA%\meet\engine\`: `uv`
создаёт окружение Python 3.12 и ставит пакеты профиля (CUDA ≈ 3 ГБ, CPU ≈ 1 ГБ).
Установка идемпотентна и возобновляема, лог — `%LOCALAPPDATA%\meet\logs\engine-install.log`.
Перед установкой проверяется свободное место (≥ 5 ГБ).

**Мастер первого запуска** (при отсутствии движка или токена):

1. Железо: найден ли NVIDIA GPU → профиль и прогноз скорости.
2. Движок: установка с прогрессом.
3. Hugging Face: кнопки «Открыть страницу модели» (принять условия
   `pyannote/speaker-diarization-community-1`) и «Открыть настройки токена»
   (галочка «Read access to contents of all public gated repos»), поле токена,
   проверка доступа с различением «условия не приняты» (403) и «неверный токен»
   (401). Токен — в Windows Credential Manager. Шаг можно пропустить: расшифровка
   без разделения на спикеров, с пометкой в карточке и кнопкой «Настроить».
4. Модели (загрузка с прогрессом) → устройства записи с индикатором уровня →
   автозапись вкл/выкл → «Готово», окно сворачивается в трей.

**Данные:** записи — `%LOCALAPPDATA%\meet\recordings` (меняется в мастере и
настройках), голоса — `%LOCALAPPDATA%\meet\voices`. Существующие `voices/`,
`hotwords.txt`, `config.json` переносятся неразрушающей миграцией ветки.
В dev-режиме (запуск из репозитория) пути прежние.

**Сборка и распространение:** GitHub Actions (Windows-раннер) в форке
`rnv812/ai_transcriber` на тег `v*` собирает установщик и публикует в Releases.
Репозиторий приватный: коллеги получают доступ как коллабораторы. Проверки
обновлений в v1 нет — «О программе» показывает версию и ссылку на Releases.
Установщик не подписан; предупреждение SmartScreen описано в README и в
описании релиза.

## Ошибки

- Падение подпроцесса расшифровки → статус записи «Ошибка» с причиной, кнопки
  «Повторить» и «Открыть лог»; резидент продолжает работу.
- Падение резидента → перезапуск оболочкой (до 3 раз), затем уведомление.
- Недоступна модель pyannote → то же объяснение, что в мастере, кнопка «Исправить».
- Мало места на диске (< 5 ГБ) → предупреждение до установки движка и до записи.
- Смена/пропажа аудио-устройства → вотчдог ядра, событие видно в диагностике.
- Токен HF не пишется в логи и не покидает Credential Manager, кроме передачи
  подпроцессу через окружение.

## Тестирование

- Python: существующие тесты ветки + новые на фиксы окружения, профиль CPU,
  импорт, API голосов/аватаров/метаданных/экспорта.
- Фронтенд: `tsc --noEmit`, vitest для клиента API и состояний списка записей,
  `vite build` в CI.
- Оболочка: `cargo check`/`clippy` в CI.
- Сквозная проверка перед релизом на чистой Windows (Windows Sandbox): установка
  → мастер → запись 1 мин → расшифровка → назвать спикера → импорт mp3 встречи
  30.09 → экспорт; отдельный прогон в профиле CPU; замер RAM/CPU в простое через
  10 минут при закрытом окне (критерий < 100 МБ суммарно).

## Ассистент

Приложение не везёт свою языковую модель: оно отдаёт расшифровку и контекст
внешнему агенту из подписки пользователя. Запись и расшифровка от ассистента
не зависят — без провайдера кнопки ассистента показывают подсказку «Подключите
Claude Code или Codex», остальное работает.

**Провайдеры** (настройка `llm.provider`):

- `auto` (по умолчанию) — установленный Claude Code CLI, иначе Codex CLI;
  в настройках видно, что найдено и авторизован ли он (проверка — короткий
  тестовый вызов по кнопке «Проверить»).
- `claude-code` — нынешний путь через claude-agent-sdk; базу знаний читает
  инструментами Read/Grep/Glob только на чтение.
- `codex` — `codex exec` в неинтерактивном режиме, песочница только на чтение,
  рабочая папка — база знаний; ответ — последнее сообщение агента.
- `openai-compatible` — локальная модель (LM Studio/Ollama): получает только
  текст, базу знаний не читает; интерфейс говорит об этом прямо.

**База знаний** — одна папка в настройках (`assistant.knowledge_dir`, например
Obsidian-хранилище или документация). Агенту с инструментами она доступна на
чтение при итогах, вопросах и дайджесте — чтобы понимать термины, проекты и
людей. **Папка заметок** (`assistant.notes_dir`) — куда кнопка «В заметки»
кладёт один Markdown: заголовок, итоги, транскрипт. Прежняя настройка
`assist.vault` автора мигрирует в `knowledge_dir` и `notes_dir` (оба — его
хранилище), его конвенция заметок сохраняется при заданном vault.

**Живой режим.** Пункт трея «Начать запись с ассистентом» и такая же кнопка в
окне. Запись в этом режиме ведёт процесс ассистента (`meet assist`), резидент
его запускает, следит за ним и останавливает; обычная запись одновременно не
стартует — lock-протокол записи общий. Снимок резидента несёт `live: {active,
endpoint}`; UI подключается к потоку ассистента (лента реплик с именами из
базы голосов, дайджест, ответы на вопросы). Показ — компактная **плавающая
панель** поверх окон (не забирает фокус, раскрывается в ленту и поле вопроса,
открывается только в живом режиме) и полная версия в **карточке идущей
записи**. После остановки — обычная точная расшифровка через очередь.

**Итоги после встречи.** Карточка записи получает вкладки «Транскрипт · Итоги ·
Вопросы». «Сделать итоги» — задача очереди `summary` (подпроцесс): результат
`summary.md` в папке записи — итоги, решения, задачи (кто / что / срок),
открытые вопросы, цитаты-подтверждения; промпт запрещает досочинять и
требует ссылаться на реплики. «Вопросы» — свободный вопрос по транскрипту
(задача `ask`, ответ сохраняется в `qa.jsonl` папки и показывается лентой).

## Этапы

Каждый этап — рабочий результат и отдельный PR.

1. **Ядро:** фиксы окружения, профиль CPU, импорт, API голосов/аватаров,
   метаданные, экспорт, режим резидента без иконки.
2. **Оболочка:** трей и меню, уведомления, sidecar-резидент с перезапуском,
   окно по требованию с уничтожением при закрытии.
3. **Окно:** три колонки «Записи», карточка записи с переименованием спикеров,
   раздел «Голоса», упрощённые настройки.
4. **Ассистент:** провайдеры (auto/Claude Code/Codex/локальный), база знаний и
   папка заметок, итоги и вопросы в карточке, живой режим в панели и карточке.
5. **Упаковка:** мастер первого запуска, установка движка через uv, NSIS,
   GitHub Actions, первый релиз.

## Открытые вопросы

- Модель по умолчанию для профиля CPU (`large-v3-turbo` против `medium`) —
  решается замером на этапе 1.
- Имя продукта для установщика (рабочее — `meet`).
