# План: meet как устанавливаемое десктопное приложение

Дата: 2026-08-17. Ветка `feat/desktop-app-architecture`. Автор плана — сессия по
просьбе внешнего контрибьютора («хочу сделать нормальный UI»); реализация — по
согласованию с автором, по фазам, каждая фаза отдельным PR.

Ориентир по UX — [Handy](https://github.com/cjpais/Handy): скачал инсталлятор,
поставил, дальше всё настраивается внутри приложения. Нынешний meet устроен
противоположным образом: venv, восемь шагов установки, конфиг в блокноте,
лексика в файлах корня репозитория, токен в переменных среды.

Важная оговорка про ориентир: Handy — диктовка одной небольшой моделью, без
диаризации, без двухдорожечного захвата, без gated-моделей, поэтому он и весит
десятки мегабайт. У meet ценность именно в тяжёлом — WASAPI loopback плюс
микрофон двумя дорожками, pyannote-диаризация, база голосов, forced alignment.
**Копируем UX-контракт Handy (инсталлятор, менеджер моделей, настройки внутри,
трей, автообновление), но не его вес.** Переписывание инференса на Rust и
whisper.cpp рассмотрено и отвергнуто: замеры в `docs/2026-07-31-npu-laptop-plan.md`
показали, что стоковые модели whisper.cpp дают транскрипт без пунктуации, с
ломаными именами и зацикливаниями, а pyannote вне CPU не портирован — то есть
такой переход стоил бы диаризации, базы голосов и качества русского.

## Что мешает упаковке сегодня

**Установка** (README): venv на 3.12 → torch с cu128-индекса → `requirements.txt`
→ `pip install -e .` → ffmpeg через winget → `HF_TOKEN` в переменных среды →
принятие условий gated-модели `pyannote/speaker-diarization-community-1` на
hf.co → ярлык автозагрузки PowerShell-скриптом. Восемь шагов, в каждом из
которых обычный человек останавливается.

**Конфигурация размазана по шести местам:**

| Где | Что | Чем мешает |
|---|---|---|
| `%LOCALAPPDATA%/meet/config.json` | `auto_record`, `post_record_hook` | правится блокнотом; секция `auto_record` читается один раз при старте трея |
| `hotwords.txt`, `glossary.txt` | лексика ASR, глоссарий | `HOTWORDS_FILE = Path("hotwords.txt")` и `load_glossary(Path.cwd())` — пути от CWD, то есть от корня репозитория |
| env `HF_TOKEN` | доступ к pyannote | пользовательская переменная среды |
| env `MEET_VAULT` | папка Obsidian | только через окружение |
| `recordings/` | сами записи | относительный путь |
| код | `DAILY_WINDOW`, `MIN_CALL_S`, дефолт `Dion.exe` | константы в `tray.py` |

У установленного приложения нет «корня проекта» — значит CWD-зависимости обязаны
уйти. Это полезно само по себе, даже если UI не случится.

**Три владельца состояния и ни одного главного:** `meet` (CLI), резидентный
`meet-tray`, `meet assist` со своим aiohttp. Кто владеет записью — выясняется
сверкой pid из `recordings/.recording.lock` с pid из `tray.lock`, а «стоп»
передаётся записью слова в файл `command`. Протокол рабочий, но UI на нём
показывать состояние мгновенно нельзя.

**Прогресс не является данными.** `transcribe`, `live` и `recorder` печатают ход
работы в stdout, а под треем stdout невидим (это прямо отмечено в CLAUDE.md, и
поэтому же существует `record.log`). Ни UI, ни нормальный CLI-прогресс на этом
не построить.

**Две внешние зависимости, о которых инсталлятор должен знать.** `assist`
требует установленного Claude Code CLI (`find_cli()` ищет `claude.cmd/exe` плюс
авторизация) — значит в приложении это опциональная фича с честной проверкой.
И машины разные: по замерам NPU-плана на ноутбуке без CUDA пайплайн проходит
целиком (RTF ~0.6, диаризация на CPU — 70% времени), но качество стоковой
модели признано непригодным для саммари.

## Решения, принятые до начала работ

1. **Тонкий инсталлятор.** 20–80 МБ: оболочка, embedded-рантайм, ffmpeg. Движок
   (torch, ctranslate2, pyannote — около 3 ГБ колёс) ставится при первом запуске
   в приватный venv с прогрессом; модели качаются отдельным шагом визарда.
   Толстая оффлайн-сборка — возможный второй артефакт, не в первой версии.
2. **Полная совместимость.** CLI, `meet-tray`, сценарии CLAUDE.md, `gpu.lock`,
   файл `command`, lock-протокол и работа из репозитория продолжают работать.
   Приложение — новый слой поверх, а не замена.
3. **Абстрактный аудио-слой.** Реализации остаются Windows-only, но захват,
   детектор звонка, календарь, автозапуск, нотификации и хранение секретов
   уезжают за интерфейсы, чтобы mac/Linux можно было добавить позже без ломки
   ядра.
4. **Сменные бэкенды ASR.** `faster-whisper` (эталон на CUDA) и `whisper.cpp`
   (машины без CUDA) за одним интерфейсом; модель — настройка, а не константа.
5. **Сменные LLM-провайдеры.** Claude Code остаётся (вопросы по встрече,
   дайджест), рядом появляется локальная модель через OpenAI-совместимый
   эндпоинт (LM Studio, Ollama). Ни один из них не обязателен для записи и
   расшифровки.
6. **Универсальность вместо личного пайплайна.** Проект перестаёт быть
   персональной сборкой: ни `Dion.exe`, ни слот дейлика в 11:00, ни промпт про
   конкретный скилл, ни Obsidian с Outlook не должны быть зашиты в код. Всё это
   — настройки и опциональные интеграции с honest-фоллбэком «нет — работаем без».
7. **Главная поверхность UI — плавающая панель.** Не окно-приложение, а
   компактная панель поверх всех окон (ориентир — Recordly), из которой
   вызываются настройки и библиотека отдельным окном. Трей сохраняется.

## Целевая архитектура

```
┌─ Оболочка: окно + трей + нотификации + автозапуск + автообновление ──┐
│  ноль доменной логики — только вызовы API и рендер состояния         │
└───────────────────────── HTTP + SSE, 127.0.0.1, порт + токен ────────┘
┌─ meetd — движок (Python, нынешний src/meet/) ────────────────────────┐
│  единственный владелец: аудио · записи · очередь задач · настройки   │
│  GPU-семафор (публичный маркер gpu.lock сохраняется)                 │
│  файлы на диске — источник истины, индекс — только кэш               │
├─ платформенные адаптеры ─────────────────────────────────────────────┤
│  AudioCapture · CallDetector · CalendarSource · Autostart ·          │
│  Notifier · SecretStore   (Windows-реализации = нынешний код)        │
└──────────────────────────────────────────────────────────────────────┘
┌─ Инсталлятор: оболочка + рантайм + ffmpeg. Модели и движок — по кнопке ┐
└───────────────────────────────────────────────────────────────────────┘
```

### Слой платформы

`meet/platform/` — интерфейсы и Windows-реализации, собранные из существующего
кода **без изменения поведения**:

- `AudioCapture` — перечисление устройств, открытие loopback и микрофона,
  события смены дефолтного endpoint'а. Реализация — нынешние `_Track`,
  `_DefaultEndpoints`, `_find_loopback` из `recorder.py` (pyaudiowpatch + COM
  `IMMDeviceEnumerator`).
- `CallDetector` — признаки звонка. Реализация — `watch.py` (реестр
  `ConsentStore\microphone` + активные WASAPI-сессии через pycaw).
- `CalendarSource` — события дня. Реализация — `scripts/calendar_lookup.ps1`.
- `Autostart`, `Notifier`, `Shell` (открыть папку/файл), `SecretStore` (токен HF
  в Windows Credential Manager вместо переменной среды).

### Ядро домена

- `paths.py` — единственный источник путей: `data_dir()`, `recordings_dir()`,
  `models_dir()`, `logs_dir()`, `hotwords_path()`, `glossary_path()`. Два режима:
  **dev** (рядом найден `pyproject.toml` — пути как сейчас, от корня репозитория)
  и **installed** (`%LOCALAPPDATA%/meet/`). Переменные среды остаются только как
  override для тестов и dev-режима.
- `settings.py` — типизированная схема с версией и миграциями. Заменяет ручные
  `_flag()`/`_positive()` из `tray.py`, мигрирует нынешний `config.json`, env
  (`HF_TOKEN`, `MEET_VAULT`) и корневые `hotwords.txt`/`glossary.txt`. Каждое
  поле помечено: применяется на лету / требует перезапуска движка / требует
  перезапуска записи (сейчас всё неявно требует перезапуска трея).
- Прогресс — колбэки `on_progress(stage, done, total)` в `transcribe`, `live`,
  `recorder` плюс структурированный лог (JSON-строки) рядом с нынешним
  человекочитаемым `record.log`. Человекочитаемый остаётся: он документирован в
  CLAUDE.md как первоисточник при разборе «почему тишина/провал/сдвиг».

### Демон `meetd`

Один процесс, single instance, владеет сессией записи, очередью задач,
настройками и индексом библиотеки. Адрес и bearer-токен — в
`%LOCALAPPDATA%/meet/daemon.json` (ACL только текущему пользователю), порт
эфемерный, чтобы не конфликтовать с 8765 у `assist`.

Набросок контракта:

| Метод | Назначение |
|---|---|
| `GET /state` (SSE) | статус (idle/armed/recording/stopping), папка, длительность, авто или ручная, уровни двух дорожек, сигналы детектора, активные задачи |
| `POST /recording/{start,stop,cancel}` | то же, что пункты трея |
| `POST /recording/adopt` | перевод автозаписи в ручную (нынешнее поведение «Начать запись» поверх автозаписи) |
| `GET /recordings`, `GET /recordings/{id}` | библиотека: дорожки, мета, транскрипт, спикеры |
| `GET /recordings/{id}/audio` | отдача дорожки с поддержкой Range — нужна плееру, синхронному с транскриптом |
| `POST /jobs`, `GET /jobs` (SSE), `DELETE /jobs/{id}` | transcribe / enroll / summary с прогрессом |
| `GET`, `PATCH /settings` | настройки со схемой и валидацией |
| `GET /devices`, `POST /devices/test` | выбор устройств и проверка уровней |
| `GET /models`, `POST /models/{id}/download` (SSE) | менеджер моделей |
| `GET /health` | железо, CUDA, ffmpeg, состояние токена, версия движка, профиль пайплайна |
| `GET /diagnostics` | `watch.log`, `record.log`, состояние `gpu.lock` — то, что сейчас читается руками |
| `GET /calendar?at=…` | тема встречи из Outlook для заголовка транскрипта |

Два решения по исполнению:

- **Задачи — подпроцессы** (`python -m meet.jobs.worker transcribe …`). Падение
  torch/CUDA не должно убивать резидента, а VRAM гарантированно освобождается
  завершением процесса. GPU-семафор на один слот; `gpu.lock` продолжает
  писаться — это публичный контракт с voice-control.
- **Запись — поток внутри демона.** Владение аудио и вотчдог смены устройства
  уже так устроены в `recorder.py`; выносить запись в подпроцесс значило бы
  заново решать вопрос владения.

### Библиотека записей

Источник истины — файлы: папка `recordings/<дата_время>/` плюс `meta.json`
рядом с дорожками (тема встречи, участники, длительность, статусы). Индекс в
демоне — только кэш, восстанавливается перечитыванием диска. Так продолжает
работать сценарий из README «записал на ноуте → скопировал папку на десктоп →
расшифровал», и повреждение индекса не теряет данные.

### Сменные бэкенды: ASR и LLM

Обе сменные части уже имеют готовый шов в коде — новые интерфейсы почти не
добавляют абстракций, а формализуют то, что есть.

**ASR.** Сейчас это `transcribe_wav(path, hotwords)` для офлайн-прохода и класс
`Transcriber` (load / transcribe_window / unload) для живого. Интерфейс бэкенда
= ровно эти две формы:

| Бэкенд | Когда | Чем платим |
|---|---|---|
| `faster-whisper` (CUDA) | десктоп с картой; русский fine-tune large-v3 | нужен CUDA-стек в движке |
| `whisper.cpp` (ggml, Vulkan/CPU) | машины без CUDA; по замерам NPU-плана iGPU даёт 74 с на 900 с аудио | качество зависит от ggml-модели: стоковый large-v3-turbo дал транскрипт без пунктуации и с зацикливаниями |

Пословных таймкодов whisper.cpp не даёт в том же виде — и это как раз тот
случай, где выручает уже существующий forced alignment (`align.py`): пословные
времёна уточняет wav2vec2, а не декодер. Диаризация pyannote остаётся общей для
обоих бэкендов.

**LLM.** `Digester` и `QAService` уже принимают `runner` параметром — то есть
провайдер подключается новой реализацией того же вызова, без переделки логики
дайджеста и вопросов:

- `claude-code` — нынешний путь через claude-agent-sdk. Умеет читать заметки
  инструментами (Read/Grep/Glob под колбэком разрешений), требует установленного
  Claude Code CLI.
- `openai-compatible` — локальная модель через LM Studio или Ollama. Своего
  рантайма не тащим. Инструментов чтения хранилища у такого провайдера нет —
  контекст задачи ему подаётся текстом, и это ограничение должно быть видно в UI,
  а не выясняться по пустому ответу.

Оба провайдера опциональны: запись и расшифровка от LLM не зависят вообще, и
приложение обязано быть полностью полезным без единой языковой модели.

### Универсализация: что убрать из кода в настройки

Проект вырос как персональная сборка, и это зашито в код. Инвентаризация того,
что должно стать настройкой или опциональной интеграцией:

| Сейчас в коде | Куда переезжает |
|---|---|
| дефолт `["Dion.exe"]` в детекторе звонка | курируемый список известных клиентов конференций (Dion, Teams, Zoom, Discord, Slack) + свои процессы; браузерные встречи детектору принципиально не видны — там не отличить встречу от ютуба |
| `DAILY_WINDOW = ("11:00","12:00")` — слот дейлика автора | необязательное «регулярное окно» в настройках; не задано — подсказки нет |
| промпт хука про скилл `my-plugin:transcriber` и `wt`+powershell | шаблон команды после записи с подстановкой `{folder}`; дефолт — ничего не запускать |
| `scripts/calendar_lookup.ps1` (Outlook COM) | провайдер календаря: Outlook / нет / (позже ICS). Пустой ответ — не ошибка |
| Obsidian (`MEET_VAULT`, `collect_task_context`) | опциональная интеграция «папка заметок»; выключена — ассистент работает без контекста задачи |
| «Вы» как имя микрофонной дорожки | имя пользователя в настройках |
| `language="ru"`, русский fine-tune в `MODEL_NAME` | язык и модель — настройки (русский остаётся дефолтом) |
| `gpu.lock` под конкретный voice-control | настройка «уступать GPU по маркеру», путь маркера настраиваемый |

Проверка на универсальность для каждой такой точки одна: **у человека, который
поставил приложение впервые, оно должно работать без единой правки конфига — и
не упоминать чужие инструменты в интерфейсе.**

### Конвейер встречи: записал → редактор → экспорт

Сценарий целиком, каким его видит человек:

1. **Останов записи открывает редактор** — сам, без флажков. Пустого ожидания
   нет: расшифровка стартует тут же, и в редакторе видно, на какой она ступени.
2. **Спикеры.** Тех, кого узнала база голосов, редактор подписывает сам;
   остальные — «Спикер 1…N», и их называют в один клик. Названный спикер сразу
   попадает в базу, поэтому на следующей встрече он узнаётся автоматически.
3. **Чистовой текст.** Лёгкая модель (провайдер из настроек — Claude Code или
   локальная) приводит расшифровку в читаемый вид: пунктуация, склейка обрывков,
   очевидные ошибки распознавания. **Смысл не переписывается**, и сырой текст
   остаётся рядом — по нему всегда можно свериться.
4. **Экспорт** — Markdown-транскрипт, протокол встречи (решения, задачи, сроки),
   копия в буфер. Дальше — в папку, в заметки, куда угодно.

**Про «клонирование голоса»: оно уже есть, и это не нейросетевой клон, а
отпечаток.** Диаризация pyannote отдаёт эмбеддинг (центроид WeSpeaker) на
каждого спикера; `voices.py` хранит их в `voices/` и матчит косинусом с порогом
0.75 и запасом 0.05 — калибровка сделана на реальных встречах, где похожий
чужой голос давал 0.61. То есть «обучение» — это один раз назвать человека в
редакторе: отдельного тренажёра не нужно, и голос не синтезируется, а узнаётся.
Порог сознательно строгий: лучше «Спикер 2», чем чужое имя в протоколе.

Что для этого нужно построить:

- **Ф7a0 — движок и модели ставятся из приложения** (вытащено из Ф10, потому
  что без этого конвейер не пройти ни на одной чистой машине). Раздел «Движок
  расшифровки» показывает, чего не хватает, видит ли карту (nvidia-smi) и
  сколько качать, и ставит стек задачей той же очереди — CUDA-сборку или CPU.
  Раздел «Модели» — каталог, за который есть чем отвечать: русский fine-tune как
  рекомендованный, стоковая multilingual, medium для слабых машин, диаризация и
  выравнивание. Источник тот же, что у Handy, — Hugging Face; разница в том, что
  качают библиотеки движка, а кэш общий и не переезжает: уже скачанные гигабайты
  не должны качаться заново. Гейтед-модель диаризации видна как «нужен токен» до
  нажатия, а не по ошибке 401 посреди загрузки.
- **Ф7a — задачи в резиденте.** Очередь на один GPU-слот, задача =
  подпроцесс (падение CUDA не должно ронять резидента, а VRAM освобождается
  завершением процесса), прогресс ступенями в шину, `POST /jobs`, `GET /jobs`.
  Рядом с транскриптом пишется `transcript.json` — структурный источник для
  редактора (Markdown остаётся человеческим артефактом и форматом экспорта).
  Библиотека записей: `GET /recordings`, отдача дорожек с Range для плеера.
- **Ф7b — редактор.** Блоки реплик, плеер, синхронный по таймкодам,
  переименование спикеров с записью в базу голосов, пометки зон нахлёста,
  правка текста руками.
- **Ф7c — чистовой проход и экспорт.** Проход лёгкой моделью с жёстким
  запретом досочинять, протокол встречи, экспорт в Markdown.

### Оболочка: плавающая панель, окно, трей

Оболочка — Tauri 2 (следствие принятых решений: нужен тонкий инсталлятор, трей,
автозапуск, апдейтер; WebView2 на Windows 11 предустановлен, бандл — единицы
мегабайт). Три поверхности, и главная из них — не окно.

**1. Плавающая панель** — компактная, поверх всех окон, без рамки, с
перетаскиванием и запоминанием позиции; в Tauri это отдельное окно с
`decorations: false`, `transparent: true`, `alwaysOnTop: true`,
`skipTaskbar: true`. Состояния:

- *дежурю* — узкая «пилюля»: точка состояния и время; клик разворачивает;
- *звонок замечен* — предложение начать запись с обратным отсчётом автозапуска;
- *пишу* — таймер, уровни двух дорожек, «авто/вручную», стоп и отмена;
- *живой режим* — последние реплики с именами из базы голосов, поле вопроса,
  кнопка «что я пропустил»; ответ раскрывается в панели, не уводя в браузер;
- *расшифровываю* — прогресс по ступеням (конвертация → ASR → выравнивание →
  диаризация → голоса) с оценкой остатка.

Правила панели: никогда не перехватывает фокус (иначе она мешает встрече),
свёрнутая занимает минимум места, кликом мыши сквозь себя не пропускает только
свою область.

**2. Окно приложения** — вызывается из панели и из трея, всё остальное живёт
здесь: библиотека записей (тема из календаря, статусы, поиск по транскриптам),
транскрипт с плеером, синхронным по таймкодам, и переименованием спикеров с
enroll в базу голосов, база голосов, настройки (включая редакторы
`hotwords.txt` с живым счётчиком бюджета — жёсткий лимит 400 символов из
`transcribe.py` наконец становится видимым — и `glossary.txt`), диагностика.

**3. Трей** — сохраняется как есть по смыслу: иконка состояния, длительность,
«остановить/отменить», показать панель. pystray живёт до паритета.

**Диагностика** — таймлайн из `watch.log` и `record.log` по документированным в
CLAUDE.md ключевым строкам («нет данных ~N с», «сменилось дефолтное
аудио-устройство», «устройство недоступно — жду», «запись остановлена штатно»).
Это не косметика: половина CLAUDE.md посвящена разбору жалоб «не записалось /
записалось лишнее» вручную.

### Первый запуск

Визард вместо восьми шагов README: определение железа и профиля пайплайна с
честным прогнозом времени → ffmpeg (несём LGPL-сборку, шаг winget исчезает) →
установка движка с прогрессом → HF-токен с кнопкой «открыть условия модели» и
реальной проверкой доступа → загрузка моделей → выбор устройств с индикацией
уровней → автозапись (процессы звонков, `grace_seconds`, окно дейлика) →
автозагрузка и трей.

## Ограничения (нельзя нарушать)

- **`recorder.py` и `watch.py` — только извлечение интерфейсов, без изменения
  поведения.** Это самая хрупкая и самая протестированная часть (`test_recorder.py`
  и `test_tray.py` — по 23–27 КБ). Существующие тесты не переписываются, а
  дополняются. Аудио-бэкенд не меняется.
- **`gpu.lock` остаётся публичным маркером** в нынешнем формате и месте: по нему
  voice-control выгружает свою копию Whisper из VRAM.
- **Lock-протокол записи сохраняется** (`.recording.lock`, `tray.lock`, файл
  `command`): это одновременно легаси-канал сценариев CLAUDE.md и защита от
  двойной записи «CLI против приложения».
- **Работа из репозитория не ломается**: `.venv/Scripts/meet …` продолжает читать
  `hotwords.txt`, `glossary.txt` и `recordings/` из корня.
- **Токен HuggingFace не попадает в логи** и не копируется в новые места (то же
  ограничение, что в NPU-плане).
- **Локальный API закрыт**: bind только на 127.0.0.1, bearer-токен, проверка
  `Origin`. Открытый локальный сервер означал бы, что любой процесс или страница
  в браузере может включить запись микрофона.
- Записи и база голосов не попадают в git (`recordings/`, `voices/`,
  `hotwords.txt`, `glossary.txt` уже в `.gitignore`).

## Последовательность

Порядок подчинён одному правилу: **плавающая панель должна появиться как можно
раньше**, но не раньше, чем под ней будет то, что она показывает. Поэтому сначала
два коротких инфраструктурных шага, потом сразу видимый результат, и только затем
широкая часть.

Важное решение о владельце записи: **API живёт внутри резидентного трея, а не в
новом процессе.** Резидент уже всегда жив и уже владеет записью — второй владелец
означал бы гонку за устройство и за lock. Со временем этот же процесс и станет
`meetd`, дорастив очередь задач; отдельного демона рядом с треем не будет никогда.

- **Ф0. Этот документ.** Архитектура, контракт API, имена путей. — *сделано.*
- **Ф1. Развязка от среды.** `paths.py` (dev/installed), `settings.py` со схемой,
  миграциями и `patch()`; выпилены `Path.cwd()`, `Path("hotwords.txt")`,
  `Path("voices")`, `"recordings"`; CLI берёт дефолты из настроек. — *сделано
  17.08.2026, 332 теста зелёные, поведение не изменилось.*
- **Ф2. Прогресс и события как данные.** `events.py` (Event / EventBus /
  JsonlSink), ступени расшифровки как `progress`, события вотчдога записи,
  уровни дорожек для метра, `events.jsonl` рядом с `record.log`. — *сделано
  18.08.2026, 365 тестов зелёные.* Живой режим сюда не входит: у него уже есть
  свой поток строк (`on_line`), и панель заберёт его в Ф3 одним стримом.
- **Ф3. Control API внутри резидента.** HTTP+SSE в потоке трея: `/state`,
  `/events`, `/recording/{start,stop,cancel,adopt}`, `/settings`,
  `/diagnostics`; порт и токен в `daemon.json`, bind 127.0.0.1, проверка Origin.
  — *сделано 18.08.2026, 413 тестов зелёные.* `/devices` перенесён в Ф5
  (выбор устройств — часть универсализации, там же уходит автоопределение).
- **Ф4. Плавающая панель на Tauri.** Первый видимый результат: панель со всеми
  состояниями, трей-иконка оболочки, показ/скрытие, запуск резидента сайдкаром.
  — *сделано 18.08.2026;* сюда же попало окно настроек с диагностикой (оно и
  было причиной всей затеи — «конфигурируем внутри»), поэтому в Ф7 остаются
  библиотека, транскрипт с плеером и очередь задач.
- **Ф5. Универсализация.** По таблице выше. — *сделано 18.08.2026.* Схема
  настроек v2: список процессов (клиенты конференций вместо одного Диона),
  `min_call_seconds`, пост-хук как шаблон команды, `recurring_window` вместо
  окна дейлика, имя владельца микрофона, язык и модель ASR, выключаемый
  GPU-маркер. Миграция v0/v1 достраивает старому конфигу то, что раньше было
  зашито в коде, — у того, кто уже пользуется meet, поведение не изменилось.
  Не тронуто сознательно: **конвенция заметок** (`assist/context.py`,
  `_VAULT_RULES`) осталась под хранилище автора — она включается только при
  заданной папке заметок, и заменять её выдуманной «общей» конвенцией значило
  бы придумать требования; **провайдер календаря** ждёт Ф7, где библиотека
  впервые начнёт его звать (сейчас `calendar_lookup.ps1` вызывают только
  Claude-сессии, из кода к нему обращений нет); **закрепление аудио-устройства**
  не поддерживается намеренно — запись следит за дефолтными endpoint'ами и
  переживает их смену, а прибитая к устройству дорожка этот механизм сломала бы.
- **Ф6. Сменные бэкенды.** Интерфейс ASR и вторая реализация на whisper.cpp;
  LLM-провайдер `openai-compatible` рядом с `claude-code`; менеджер моделей в
  настройках. (~3–4 вечера)
- **Ф7. Конвейер «записал → редактор → экспорт».** Главная фаза продукта;
  ориентир по сценарию — Recordly. Останов записи **сам открывает редактор**
  (не по флажку в настройках — так задумано), в редакторе идёт расшифровка с
  прогрессом, расставляются спикеры, наводится чистовой текст лёгкой моделью,
  и результат экспортируется. Разбита на три части — см. ниже. (~8–12 вечеров)
- **Ф8. Платформенные адаптеры.** `meet/platform/*` — извлечение интерфейсов из
  `recorder.py`, `watch.py`, календаря; поведение неизменно. Пользователь ничего
  не замечает, поэтому фаза стоит после видимых. (~2 вечера)
- **Ф9. CLI как клиент.** `meet *` работает через резидента, если он жив, иначе
  локально; флаг `--local`. Проверка — все сценарии CLAUDE.md вручную. (~1–2 вечера)
- **Ф10. Инсталлятор, визард, апдейтер.** NSIS/MSI, ffmpeg в комплекте,
  установка движка при первом запуске, загрузка моделей, updater, README и
  CLAUDE.md. (~3–4 вечера; инсталляторы всегда дольше оценки)
- **Ф11. Полировка.** Тёмная тема, анимации панели, waveform, горячие клавиши,
  пустые состояния.

pystray удаляется только после паритета трея в оболочке, и до тех пор обе точки
входа сосуществуют — от двойной записи защищает lock-протокол.

## Риски

1. **Первый запуск зависит от сети:** установка ~3 ГБ колёс может прерваться.
   Лечится приватным venv в `%LOCALAPPDATA%/meet/engine/<версия>/`, идемпотентной
   и возобновляемой установкой, атомарным переключением версии, кнопками
   «переустановить движок» и «проверить целостность», подробным логом установки.
2. **Gated-модель pyannote неустранима** без смены модели диаризации. Максимум —
   сделать шаг визарда понятным и различать ошибки «условия не приняты» и
   «токен неверен». Поиск негейтед-альтернативы — отдельная задача-замер.
3. **Ноутбук без CUDA:** `/health` определяет профиль, UI честно показывает
   ожидаемое время и качество и предлагает штатный путь из NPU-плана — писать на
   ноутбуке, расшифровывать на десктопе. Перенос записи стоит со временем
   сделать кнопкой.
4. **SmartScreen и антивирусы** на неподписанном инсталляторе. Либо подпись
   (деньги), либо честное предупреждение в README.
5. **Обратная совместимость конфига:** у автора уже есть рабочий `config.json`,
   `hotwords.txt` и база голосов. Миграция обязана быть неразрушающей и
   обратимой (старые файлы не удаляем, а помечаем перенесёнными).
6. **Расползание объёма.** Ф1–Ф5 — инфраструктура без видимого результата;
   соблазн начать с картинок и оставить фундамент недоделанным.

## Решённое по ходу

- **`assist` остаётся** и получает вторую опцию — локальную модель. Вопросы по
  встрече («что я пропустил») названы главной причиной держать LLM в продукте.
- **Папка записей по умолчанию** — `%LOCALAPPDATA%/meet/recordings` в
  установленном режиме (не синхронизируется OneDrive, в отличие от Документов),
  с явным выбором в визарде. В dev-режиме — `recordings/` в корне, как было.
- **Кэш моделей HuggingFace не переносим**: уже скачанные гигабайты не должны
  качаться заново. `models_dir()` — только для того, что качает само приложение
  (ggml-модели whisper.cpp).
- **Пост-хук** становится настраиваемым шаблоном команды, а не зашитым запуском
  Claude Code в Windows Terminal; дефолт для нового пользователя — ничего не
  запускать.

## Открытые вопросы

- Имя и иконка продукта: `meet` — рабочее имя внутри репозитория, для
  инсталлятора нужно что-то однозначное.
- Подписывать ли инсталлятор (SmartScreen) — вопрос денег, не техники.
- Нужна ли толстая оффлайн-сборка вторым артефактом или тонкого достаточно.

## Аудит и стабилизация (18.08.2026)

(28 агентов). Подтверждено 13 багов (0 ложных), все починены пачкой, каждый —
