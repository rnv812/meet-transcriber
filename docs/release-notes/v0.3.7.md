Выпуск **Meet** 0.3.7 (черновик). Реакции на сообщения ассистента стали
понятнее: у них формальные подписи, в подсказке сказано, что будет, а после
нажатия видно, что ассистент это учёл. Окно ассистента держит одну раскладку
при любой ширине: чат всегда на месте, а колонку расшифровки рядом можно
расширить намного сильнее. Ассистенту можно больше — файлы вне встречи, MCP,
веб и действия, — но только с вашего согласия: действия — по карточке Meet
на каждый вызов.

## Главное

- **Реакции с понятными подписями.** Вместо «норм», «не норм» и «вопрос» —
  👍 «Полезно», 👎 «Не по теме» и ❓ «Поясни».
  - 👍 «Полезно» — ассистент будет писать больше такого.
  - 👎 «Не по теме» — сообщение мимо: не та тема, неверное допущение или не
    к месту. Ассистент поймёт, в чём промахнулся, скорректирует, о чём
    пишет, и эту мысль повторять не будет. Частоту 👎 не меняет — её задаёт
    только «Как часто писать».
  - ❓ «Поясни» — ассистент объяснит, на что опирался и что предлагает.
  - Что будет, написано в подсказке у кнопки. При наведении на сообщение
    рядом с эмодзи видна подпись, у поставленной реакции — всегда. В узкой
    панели — только эмодзи с подсказкой.
- **Видно, что реакция учтена.** Сразу после нажатия под сообщением
  появляется «Учту: такое полезно» или «Учту: скорректирую, о чём пишу» и
  через пару секунд гаснет — остаётся нажатая реакция. После ❓ под
  сообщением видно «Ассистент поясняет…», пока не придёт ответ. Ответ помечен
  «пояснение», а ссылка «к сообщению …» прокручивает к поясняемому сообщению
  и подсвечивает его. Снятая реакция ничего не показывает.
- **Одна раскладка, чат не прячется.** Панель ассистента больше не
  перестраивается сама при сужении окна: нет ни полосы расшифровки над чатом,
  ни строки с последней репликой вместо расшифровки. При любой ширине слева —
  колонка расшифровки, справа — чат. В узком окне обе колонки ужимаются, а
  убрать расшифровку можно только самому: кнопкой «‹» на разделителе (вернуть
  — «›»), выбор запоминается. Пока ассистент подключается, чат уже на месте —
  «Подключаюсь к ассистенту…» видно в строке ввода; при обрыве связи чат
  тоже остаётся.
- **Колонка расшифровки шире.** Разделитель между расшифровкой и чатом
  больше не упирается в 640 px: колонку можно тянуть хоть на полэкрана. Чату
  остаётся не меньше 280 px, расшифровке — не меньше 160 px. Если окно
  сузить, колонка ужимается, а когда окно снова станет шире, вернётся к
  выбранной ширине. Стрелки на разделителе, двойной щелчок и Enter работают
  как раньше.

## Профили ассистента: «Рабочая встреча» и «Личный»

Ассистента можно звать не только на рабочие встречи. Профиль задаёт его роль
на сессию.

- **«Рабочая встреча»** — как раньше. Ассистент видит карту базы знаний и
  прошлые встречи группы, предлагает заглянуть в них (открывает только с
  вашего согласия), подсказывает по делу и закрепляет вопросы, заданные вам
  на встрече.
- **«Личный»** — для созвона, стрима, видео или подкаста. Сначала
  ассистент понимает по репликам, что это, и один раз коротко говорит об этом.
  Дальше он отвечает на ваши вопросы и даёт краткое содержание по просьбе или
  после большой законченной части. Тон нейтральный: без рабочей рамки,
  советов, сроков и задач. Закрепляет сообщение, только если к вам обратились
  по имени.
- **База знаний в «Личном» закрыта не только инструкцией.** Карта базы и
  список прошлых встреч модели не уходят. Без вашей просьбы ассистент читает
  только папку этой записи и то, что вы приложили.
  - **С расширенными возможностями** Claude Code по вашей просьбе читает
    файлы и ищет в вебе. Базу знаний и другие записи библиотеки Meet
    блокирует на любом уровне согласия. Их не открывают ни кнопка «Да,
    глянь», ни «Разрешать такое до конца встречи». Обойти запрет нельзя и
    через `..`, поиск или команды.
  - MCP-серверы пользователя в этом профиле не подключаются. Каждая
    команда, кроме простого чтения, идёт своей карточкой.
  - **Без расширенных возможностей** папок базы знаний и библиотеки нет
    среди папок модели, Claude Code получает запрет на чтение базы, а
    запасные запросы локальной модели к базе отключены.
  - У Codex и OpenCode чтение вне папки записи ограничено только
    инструкцией. В шапке это видно: «База знаний закрыта только просьбой».
  - В шапке сессии — «видит: только разговор», а с вложениями — «разговор и
    ваши материалы (…)». Чипов-источников с документами базы знаний в этом
    профиле нет.
- **Сводка и итоги — тоже без базы и без рабочей рамки.** «Сводка на
  сейчас» в «Личном» ведёт главные мысли и вопросы без ответа, без
  решений и задач, без глоссария и контекста задачи. Итоги после записи
  (`summary.md`) становятся кратким содержанием: «Кратко», «Главные мысли»,
  «Вопросы без ответа», «Цитаты». Их пишут без базы знаний. «Продолжить
  разговор» говорит ассистенту «Запись уже закончилась…», а итоги даёт, только
  если они собраны в этом профиле.
- **Выбор — одним щелчком при старте.** В меню «Начать запись ▾» два пункта:
  «С ассистентом · Рабочая встреча» и «С ассистентом · Личный». Так же
  во время обычной записи: «Включить ассистента · …». Профиль из настроек
  стоит первым и помечен «(по умолчанию)». Трей запускает с профилем по
  умолчанию.
- **Профиль виден и меняется по ходу.** В шапке сессии — чип профиля, рядом
  с «Как часто писать» — переключатель «Профиль». Смена действует только на
  эту сессию. Ассистент получает заметку «Профиль сменён на … — это заменяет
  прежние правила роли: …», как при смене частоты. Claude Code перезапускается
  с продолжением сеанса, уже с папками и инструкцией нового профиля. Codex и
  OpenCode при продолжении инструкцию заново не читают, поэтому начинают новый
  сеанс с инструкцией профиля и затравкой из журнала чата.
- **Профиль по умолчанию** — в настройках ассистента («Профиль по
  умолчанию»), `assist.profile`: `work` или `personal`. По умолчанию — `work`.
- **После встречи** вкладка «Ассистент» показывает, в каком профиле шла
  сессия. «Продолжить разговор» продолжает в том же профиле: он хранится в
  журнале встречи, в `assistant/sessions.json`. В «Личном» быстрые
  вопросы другие: «Краткое содержание», «О чём это было?», «Главные мысли».
- Для проверки перед выпуском у `scripts/smoke_participant.py` есть сценарий
  `--profile personal`: заготовленный стрим, вопрос, просьба прочитать соседнюю
  запись через `../`, вопрос про базу знаний и просьба о кратком содержании.
  Без `--run` он только печатает план.
- **Остановить без сохранения.** Запись, которая не нужна, можно
  остановить без следа: «Стоп ▾ → Остановить без сохранения…» в окне, значок
  с корзиной в панели ассистента, ссылка под «Остановить» в панели строки
  меню macOS и пункт меню трея (раньше — «Отменить запись…» только в трее).
  Сначала вопрос «Остановить без сохранения? Запись и всё, что с ней связано,
  будут удалены без возможности восстановления.» — по умолчанию «Отмена», Esc
  тоже отменяет. «Удалить запись» удаляет папку записи с лентой, чатом
  ассистента, вложениями и материалами и сеанс ассистента в истории Claude
  Code (и папку проекта вкладки «Агент» со строками `history.jsonl`), Codex
  (`codex delete`) или OpenCode. Ни расшифровки, ни хука, ни выгрузки. Чего
  удалить нельзя (сеанс Codex или OpenCode во вкладке «Агент» без id), вопрос
  называет прямо.
- **Временная встреча с ассистентом.** Новый пункт рядом с «С ассистентом» —
  в «Начать запись ▾», в меню трея и в панели строки меню macOS. Это
  разговор с ассистентом вживую, который не идёт в историю: запись и чат
  работают как обычно, но во временной папке вне библиотеки — встречи нет ни
  в списке, ни в поиске, ни в группах. Ассистент не сохраняет сеанс у
  провайдера (Claude Code — без сохранения, Codex — `--ephemeral`, OpenCode
  — сеанс удаляется после ответа). В шапке панели, у кнопки записи и в
  трее — «Временная — не сохранится». «Стоп» спрашивает «Временная встреча
  закончится и будет удалена.» и удаляет всё: папку, чат, материалы и сеанс
  ассистента у провайдера — без расшифровки, анализа, названия, выгрузки в
  базу знаний и пост-хука. «Сохранить как обычную встречу» во время неё
  превращает её в обычную запись: после остановки она ляжет в библиотеку и
  расшифруется. Оставшиеся после сбоя временные встречи удаляются при
  следующем запуске.

- **Ассистенту можно больше — но только с вашего согласия.** Новый
  выключатель «Расширенные возможности ассистента (файлы вне встречи, MCP,
  веб) — по согласию» в «Настройки → Ассистент», по умолчанию включён. С
  Claude Code ассистенту доступно всё, что умеет модель на этом компьютере:
  любые файлы (например, «Загрузки»), база знаний и прошлые встречи, веб,
  ваши MCP-серверы (Jira, GitLab и другие — из обычных настроек Claude Code)
  и команды.
  - **Без вашей просьбы** он читает только эту встречу и то, что вы добавили
    в чат. Остальное предлагает кнопками: вы говорите на встрече «да, файл
    скачал, сейчас посмотрю» — он пишет «Я тоже гляну этот файл из
    Загрузок?» [«Да, глянь» | «Не надо»]; прозвучал номер задачи —
    «Проверить задачу ABC-123 в Jira?».
  - **По вашей просьбе** — ваше сообщение ассистенту, нажатая кнопка или ❓ —
    он сразу, как обычный агент, читает файлы, ищет в вебе, смотрит через MCP
    (всё, что ничего не меняет: в имени инструмента нет «create», «update»,
    «delete», «send», «fetch» и т. п.) и выполняет простые команды чтения
    (`ls`, `cat`, `head`, `rg`, `grep`, `git status/log/diff/show/branch`,
    `find` — одна команда, без `;`, `|`, `>`, `$`, шаблонов, с абсолютными
    путями и только безопасными флагами). Согласие — на эту просьбу, а не до
    конца встречи. После чтения он говорит, на что опирался.
  - **Остальное — карточкой Meet.** Другие команды, запись или правка файла,
    создание или правка задачи, инструменты MCP, которые что-то меняют,
    открытие веб-страницы, навык: Meet показывает в чате карточку с точным
    вызовом и кнопками **«Разрешить один раз»**, **«Разрешать такое до конца
    встречи»** и «Отклонить». Длинный вызов показан началом и концом с
    пометкой «…скрыто: N строк…» посередине («Показать полностью» — по
    желанию); пробелы и пустые строки — видимыми пометками, так что хвост не
    спрятать. Кнопки самого ассистента («Да, создай») действия не разрешают.
    Нет ответа за 2 минуты — не выполняется. Карточка, которая ждёт решения,
    видна над лентой; Esc — «Отклонить». Так же — во вкладке «Ассистент» после
    встречи и на странице `meet assist`. Вызов показан по-человечески:
    запись — «Записать файл: путь» и содержимое; правка — «Изменить файл:
    путь» и строки «− было / + стало» (замена всех вхождений — явно);
    команда — как есть; MCP — аргументы с отступами, пути с одной «\».
  - **«Разрешать такое до конца встречи»** — дальше без карточки: тот же
    инструмент MCP, тот же сайт, та же простая команда (по первому слову, а у
    `git`, `npm`, `docker`… — со словом подкоманды: «Bash: git status»; у
    `curl`/`wget` — тот же сайт и метод), изменение файлов в папке встречи
    или в папке, куда вы уже разрешали запись («изменение файлов в …»: и
    запись, и правка — Write, Edit, MultiEdit; закрытые папки внутри — всё
    равно карточкой или отказом; в профиле «Личный» — не предлагается).
    Публикация и установка (`git push`, `npm publish`, `npm install`…),
    интерпретаторы с кодом (`python -c`, `node -e`…) и удаление (`rm`, `del`, `mv`…) так не
    разрешаются — каждый раз карточкой. Разрешения видны в шапке чата («разрешено:
    Bash npm, MCP jira: create_issue») и снимаются «×»; после встречи не
    действуют. Без вашей просьбы (ход по репликам) они не работают.
  - У временной встречи разрешения «до конца встречи» хранятся в её журнале
    и удаляются вместе с ней.
  - Лишнее Meet блокирует сам, а в чате появляется тихая строка «Ассистент
    хотел … — запрос заблокирован».
  - В шапке чата — «может: файлы, MCP (Jira, GitLab…), веб — по вашему
    согласию» с именами MCP-серверов, которые назвал Claude Code.
- **Кнопки ассистента нажимаются один раз**: второе нажатие на то же
  сообщение не уходит.

## Безопасность — честно

- Разрешённое ассистент делает **с вашими правами**: читает ваши файлы,
  ходит в Jira и GitLab под вашей учётной записью, выполняет команды на
  вашем компьютере. Прочитанное уходит выбранной модели.
- Текст файлов, веб-страниц, задач и реплик встречи может пытаться
  командовать ассистентом. Без вашей просьбы он не прочтёт ничего вне
  встречи; по просьбе — читает и смотрит через MCP без вопросов (как
  обычный агент), а действия выполняет только через карточку или
  разрешение «до конца встречи». Читайте карточку: в ней точный вызов.
  Адрес, сайт или почта в аргументе MCP-инструмента — тоже карточкой (так
  данные не утекут через «читающий» инструмент), если сайт не разрешён.
  MCP-инструменты, чьё имя не похоже на запись, выполняются без вопроса;
  `git commit` и `git pull`, разрешённые до конца встречи, запускают хуки
  самого репозитория.
- Невидимые символы (смены направления текста, нулевой ширины, необычные
  пробелы, пустые хангыль и брайль) в вызове не допускаются — такой вызов
  Meet блокирует: им нельзя подделать карточку. Флаги вроде «без песочницы»
  (`dangerouslyDisableSandbox`) показываются в карточке крупно.
- **Закрыто всегда:** папки «Не показывать ассистенту»; ключи и пароли —
  `~/.ssh`, облачные ключи, настройки Claude Code и Codex, профили браузеров,
  хранилища паролей Windows, служебные файлы Meet (его токен и настройки),
  `.env` вне встречи; подагенты, фоновые команды и расписания; обращения к
  локальным адресам (127.0.0.1, localhost) — в том числе к API самого Meet.
  Команду, в которой упомянута закрытая папка (или папка базы над ней),
  Meet не выполнит; но в команде закрытый путь можно спрятать — потому
  каждая команда и идёт через карточку.
- **Свои хуки Claude Code** (настройки `hooks`) в ассистенте не
  запускаются: они получали бы текст встречи. Ваши CLAUDE.md, навыки и
  плагины ассистент видит.
- **Codex и OpenCode** остановить вызов до вашего решения не дают,
  поэтому с этим выключателем им — **только чтение файлов по вашей
  просьбе**: MCP-серверы, веб и действия выключены (Codex — песочница
  «только чтение», MCP-серверы выключены, а если их список не прочитался —
  без `config.toml` вовсе). Чтение файлов вне встречи без просьбы им
  запрещено только инструкцией. MCP, веб и действия — только с Claude Code.
  OpenCode на живой установке не проверялся.
- Выключатель выключен — как в 0.3.6: ассистент читает встречу, базу знаний
  и прошлые встречи. Codex и тогда загружает свои MCP-серверы из своих
  настроек — так было и в 0.3.6.

## Изменения

- **Живая лента различает собеседников звонка.** Раньше весь звук из
  динамиков подписывался одним «Собеседник», сколько бы людей ни говорило.
  Теперь, как только второй голос наберёт около 15–20 секунд речи, реплики
  подписываются «Собеседник 1», «Собеседник 2» и так далее, а прежние строки
  переподписываются задним числом. Голос из базы голосов подписан именем.
  Пока говорит один человек, подпись прежняя — «Собеседник»: другая
  интонация или шум линии его не делят. Короткие ответы («Да, слушаю»)
  подписываются по голосу. Реплику, в которой распознавание склеило двоих,
  лента делит на две строки. Подписи живой ленты предварительные — об этом
  напоминает строка над лентой, а ассистент получает заметку «Meet уточнил
  говорящих: …», когда они меняются. В расшифровке после встречи нумерация
  своя («Спикер N»).
  - Работает и без базы голосов: модель голосов в живом режиме теперь
    загружается и тогда, если она скачана вместе с моделью диаризации
    (посреди встречи она не качается). Это ещё около 400 МБ памяти и
    несколько секунд фоновой загрузки; выключить — `assist.voices: false` в
    `config.json` или `meet assist --no-voices`.
  - Порог, при котором кластеры голоса собеседников сливаются в один, ниже,
    чем раньше (0.57 вместо 0.65), — и при непустой базе голосов: один
    человек, разделённый по ошибке, склеивается быстрее.
- **Вкладка «Агент» всегда запускает Claude Code с «Моделью Claude Code».**
  Модель вкладки теперь та же, что у итогов и живого ассистента: «Модель
  Claude Code» в настройках, а если её не выбирали — **sonnet**. Так и в
  новой сессии, и в «Продолжить прошлую». Раньше `claude` во вкладке шёл
  без `--model` и брал модель из своего `~/.claude/settings.json` или свою
  по умолчанию — самую новую, а «Продолжить прошлую» — модель прежнего
  сеанса. Модель видно в строке «Команда запуска» и в шапке вкладки
  («модель: opus»). Кому во вкладке нужна другая модель: выберите её в
  «Модели Claude Code» (например, `opus` или `fable`) или задайте свой
  `--model` в «Дополнительных параметрах» (либо `ANTHROPIC_MODEL` в
  «Переменных окружения») — они важнее. Серый пример в пустом поле «Дополнительные параметры»
  больше не `--model opus` — его принимали за заданную модель.
- **Видно, какая модель отвечает на самом деле.** В шапке агента-участника —
  модель, которую запустил Claude Code, а не только имя из настроек. Если
  он запустил другую модель (псевдоним переопределён переменной окружения
  вроде `ANTHROPIC_DEFAULT_OPUS_MODEL` или модель недоступна подписке), рядом —
  предупреждение «Запущена …, в настройках — …». Фоновые задачи пишут такое
  же предупреждение в журнал.
- То же — на вкладке «Ассистент» карточки после встречи и на странице
  `meet assist` в браузере.
- В прежней раскладке ассистента (без чата) колонка подсказок тоже больше не
  ограничена 960 px.
- `assistant/sessions.json` помнит и прежние id сеансов ассистента (после
  смены сеанса — например, ветки после картинки), чтобы удаление без следа
  забывало все. У Claude Code вместе с сеансом удаляются и его спутники в
  папке настроек (история правок файлов, окружение, задачи).
- Забытый сеанс Codex удаляется официальной командой `codex delete --force`
  — вместе с потоком в его sqlite-хранилищах (раньше удалялся только файл
  rollout, а разговор оставался в `state_5.sqlite` и `thread_history_1.sqlite`).
- Ответы службы записи и страницы ассистента не кешируются на диске
  (`Cache-Control: no-store`).
- API резидента: `POST /live/start` принимает `{"temporary": true}`, новый
  `POST /recording/keep` — «Сохранить как обычную встречу»; в `/state` —
  `temporary`, у `last_stop` — причина `temporary`; событие `record.kept`.
- В `assistant_chat.md` и в переписке, которую видит ассистент, реакции
  подписаны по-новому («реакции: 👍 Полезно»), у ответа на ❓ — «пояснение к
  m…». В журнале реакции хранятся теми же эмодзи, старые встречи читаются
  как раньше.
- Claude Code ассистента запускается с вашими обычными настройками,
  навыками и MCP-серверами (раньше — в изоляции от них), но без ваших хуков.
  Серверы, добавленные только для одного проекта (`claude mcp add` без
  `-s user`), ему не видны: он работает в своей служебной папке.
- Если Claude Code не включил проверку согласия (очень старая версия), ход
  ассистента завершается ошибкой с советом обновить Claude Code или выключить
  расширенные возможности — без проверки он не работает.
- `scripts/probe_claude_gate.py` проверяет договор Meet с установленным
  Claude Code без вызова модели; `scripts/smoke_participant.py
  --only-freedom` — то же на живой модели: файл во временных «Загрузках»,
  «Да, глянь», запись через карточку, список MCP-серверов.

## Обновление

- Ничего делать не нужно. Отклики «Учту: …» показывает само окно, в журнал
  встречи они не пишутся.
- Профиль по умолчанию — «Рабочая встреча»: ассистент ведёт себя как в
  0.3.6. Встречи прошлых версий, где ассистент уже отвечал, остаются в
  «Рабочей встрече», какой бы профиль по умолчанию ни был выбран.
- В черновых сборках 0.3.7 профиль «Личный» назывался «Нейтральный»
  (`neutral`). Такое значение в настройках, журнале встречи, API и у
  `--profile` читается как «Личный» (`personal`).
