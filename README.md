# meet — локальный транскрибатор встреч

Запись и расшифровка рабочих встреч целиком на своей машине (GPU).
Ничего не отправляется наружу.

## Установка

Для Windows 10/11 x64, без прав администратора.

1. Скачайте `meet_<версия>_x64-setup.exe` из Releases форка:
   https://github.com/rnv812/ai_transcriber/releases (репозиторий приватный —
   нужен доступ коллаборатора). Рядом лежит `SHA256SUMS.txt`; сверить файл:
   `certutil -hashfile meet_<версия>_x64-setup.exe SHA256`.
2. Установщик не подписан, и Windows SmartScreen его остановит: «Система
   Windows защитила ваш компьютер» → **Подробнее** → **Выполнить в любом
   случае**.
3. Программа ставится в профиль пользователя (`%LOCALAPPDATA%\meet`), ярлык
   «meet» появляется в меню «Пуск» и на рабочем столе. При первом запуске
   откроется мастер: определит видеокарту, скачает движок расшифровки
   (Python, PyTorch и библиотеки распознавания: для NVIDIA — около 4,5 ГБ
   загрузки и 8 ГБ свободного места, для CPU — около 0,6 ГБ и 3 ГБ),
   поможет подключить токен Hugging Face для разделения на спикеров (шаг
   можно пропустить), скачает модели (ещё до 4,5 ГБ), проверит устройства
   записи и предложит запускаться вместе с Windows. Дальше приложение живёт
   в трее.

**Где лежат данные.** В `%LOCALAPPDATA%\meet`, рядом с программой: записи
(`recordings`, папка меняется в настройках), база голосов (`voices`),
настройки (`config.json`), журналы (`logs`), движок (`engine`, несколько
гигабайт). Модели распознавания — в кэше Hugging Face
(`%USERPROFILE%\.cache\huggingface`), скачанные пакеты — в кэше uv
(`%LOCALAPPDATA%\uv\cache`). Токен Hugging Face — в диспетчере учётных данных
Windows (учётные данные Windows, адрес `meet`).

**Удаление.** «Параметры → Приложения → meet → Удалить» убирает программу,
ярлыки и автозапуск, но не данные: записи, голоса, настройки и движок
остаются в `%LOCALAPPDATA%\meet`, и переустановка подхватит их как есть.
Галочка деинсталлятора «Удалить кэш окна» эту папку тоже **не** трогает: она
чистит только служебный кэш окна (`com.meet.desktop`).
Чтобы убрать всё, после удаления сотрите папку `%LOCALAPPDATA%\meet`, при
желании — кэши `%LOCALAPPDATA%\uv\cache` и `%USERPROFILE%\.cache\huggingface`
(они общие с другими программами на uv и Hugging Face) и запись `meet` в
диспетчере учётных данных.

Собрать установщик самому — `scripts/build_release.ps1 -Version x.y.z`
(нужны uv, Node.js и Rust). В GitHub Actions его собирает и публикует тег
`v*` (`.github/workflows/release.yml`); описание релиза берётся из
`docs/release-notes/<тег>.md`.

## Обновление

Новую версию ставят поверх: скачайте установщик и запустите его — записи,
голоса и настройки сохранятся.

- **Проверка по кнопке.** «Настройки → О программе → Проверить обновления»
  сверяет версию с последним выпуском на GitHub
  (https://github.com/rnv812/meet-transcriber/releases). Сама программа за
  обновлениями в сеть не ходит. Если есть новая версия, кнопка «Скачать и
  установить» скачает установщик, сверит его SHA-256 с `SHA256SUMS.txt`
  выпуска и запустит его, а приложение штатно закроется. Во время записи
  обновиться нельзя: сначала остановите запись.
- **Установщик.** Если найдена прежняя версия, первая страница так и
  говорит: «Найдена установленная версия X. Обновить до Y? Записи, голоса и
  настройки сохранятся.» Вариант «Обновить до Y» выбран сразу: новая версия
  ставится поверх, деинсталлятор не запускается. Для той же версии
  предлагается «Переустановить», для более ранней — «Откатиться на Y» с
  предупреждением. Вариант «Сначала удалить версию X» тоже не трогает
  данные.
- **Запущенное приложение** установщик просит выйти штатно, как «Выход» в
  трее, и ждёт до 90 секунд, пока служба записи сохранит идущую запись
  («Сохраняю запись…»); только после этого заменяются файлы. Версию 0.1.0
  так попросить нельзя — установщик предложит закрыть её кнопкой OK и тоже
  дождётся сохранения записи.
- **Папку установки при обновлении не меняйте** — оставьте предложенную
  `%LOCALAPPDATA%\meet`.
- **После установки** на странице «Готово» стоит галочка «Запустить meet» —
  новая версия запускается сама и один раз сообщает «meet обновлён до Y»
  (если уведомления не выключены).

Мастер второй раз не открывается. Движок у каждой версии свой
(`engine\<версия>`): при первом запуске новой версии приложение само ставит
его в фоне тем же профилем (CUDA или CPU), что был у прежней. Пакеты почти
все берутся из кэша uv, поэтому обычно хватает минуты-двух. Ход виден в
подсказке значка в трее («обновляю движок: шаг N из 4»). Запись в это время
недоступна. Когда новый движок заработает, прежний удаляется. Если поставить
не вышло, придёт уведомление «Не удалось обновить движок»: откройте окно и
поставьте движок кнопкой «Установить». Пересобранный установщик той же
версии (например, финальная 0.1.0 поверх 0.1.0-rc1) движок заново не
ставит, а при старте за секунды заменяет в нём только пакет meet.

## Использование

Проще всего — двойной клик по `meet.bat` в корне проекта: откроется меню
(записать / транскрибировать последнюю запись / транскрибировать файл).
Активировать venv не нужно. Те же команды из терминала:

    meet record                      # записать встречу (Ctrl+C — стоп)
    meet transcribe recordings/...   # папка записи → transcript.md
    meet transcribe запись.mp4       # или любой аудио/видеофайл → запись.md

Импорт чужой записи: окно приложения → перетащить файл; из терминала —
`meet import <файл>` (см. «Без приложения»); из API — POST /recordings/import.

Объединение встреч: одна встреча разбилась на несколько записей (вышли и
зашли заново дольше, чем ждёт автозапись) — в списке отметьте их Ctrl- или
Shift-щелчком (Ctrl+A — все) и нажмите «Объединить». Записи склеиваются по
времени в новую (отсутствующая в части дорожка — тишиной той же длины) и
расшифровываются заново целиком: спикеры общие, на стыках — «— перерыв N
мин —». После расшифровки исходные удаляются, если не отмечено «Сохранить
исходные записи»; если части выгружались в базу знаний, туда же выгружается
объединённая, а прежние папки частей остаются как были. Из терминала —
`meet merge`, из API — POST /recordings/merge `{"ids": [...], "keep_originals": false}`.

Полезные флаги transcribe:

    --speakers N      # число говорящих, если уверены (обычно авто точнее;
                      # для папки записи — не считая вас)
    --hotwords "..."  # термины через запятую — подсказка распознаванию
    --no-align        # отключить forced alignment (по умолчанию включён:
                      # уточняет пословные таймкоды wav2vec2 — точнее стыки спикеров)
    --no-overlap      # отключить overlap-aware диаризацию (по умолчанию включена:
                      # перебивание не рвёт фразу, зоны нахлёста помечены «(нахлёст)»)

Подсказка лексики берётся из двух файлов в корне (в git не попадают):
`hotwords.txt` — приоритетное ядро терминов, идёт в декодер (жёсткий лимит
~400 симв.); `glossary.txt` — полный глоссарий без лимита, его читает LLM при
работе с транскриптом. `--hotwords` добавляется к `hotwords.txt` разово.

## Без приложения

Всё, что умеет окно, работает и из терминала — без резидента, без вопросов и
без браузера. Запись указывается папкой или id (имя папки в папке записей);
`--json` печатает результат одним JSON-документом. Код выхода: 0 — готово,
1 — ошибка (текст в stderr), 2 — неверные аргументы.

    meet import звонок.mp4                 # в библиотеку + расшифровка; печатает папку записи
    meet import звонок.mp4 --no-transcribe # только положить в библиотеку
    meet export 2026-09-29_15-30 --format srt            # md | txt | srt — в stdout
    meet export recordings/<папка> --format md --out встреча.md
    meet voices list                       # имя · встреч · мин речи · фото
    meet voices rename "Демьян" "Демьян Петров"  # и в транскриптах библиотеки
    meet voices merge "Даня" "Демьян Петров"   # слить два голоса одного человека
    meet voices delete "Демьян" --yes        # без --yes — отказ, а не вопрос
    meet voices avatar "Демьян" фото.jpg     # --clear — убрать фото
    meet summary <папка>                   # итоги → summary.md (--provider codex — на этот раз)
    meet ask <папка> "Кто взял задачу?"     # ответ дописывается в qa.jsonl
    meet kb-export <папка>                 # в базу знаний: export.meetings_dir/<шаблон папки>
    meet merge <запись> <запись> [--keep]  # объединить и расшифровать; без --keep исходные удаляются

Модель для `summary`/`ask` — из настройки `llm.provider`; не подключена ни
одна — код 1 и подсказка.

## Имена спикеров и база голосов

Незнакомые спикеры выходят как «Спикер 1/2/…» — поправить проще всего заменой
в md. Чтобы имена подставлялись сами в следующий раз, запомните голоса в базе:

    meet enroll recordings/<папка> "Спикер 1=Демьян Петров" "Спикер 2=Пётр Сидоров"

База — папка `voices/` в корне (в git не попадает). Если она есть, знакомые
голоса при транскрибации именуются автоматически (в логе — `голоса: SPEAKER_XX
→ Имя`). Рядом с транскриптом появляется `*_speakers.json` (эмбеддинги для
enrollment) — не удалять, из него `enroll` и берёт голоса.

## Живой режим (ассистент)

Подсказки по ходу встречи — запись + потоковая расшифровка + дайджест и ответы
на вопросы, всё локально:

    set MEET_VAULT=C:\путь\к\заметкам   # опционально: контекст задач из Obsidian
    meet assist                          # --task <slug> — привязать к хабу задачи

В выводе появится адрес вида `http://127.0.0.1:8765/` — дайджест и вопросы на
этой странице. Остановка — Ctrl+C, после чего можно прогнать точную
транскрибацию `meet transcribe recordings/<папка>`.

При непустой базе голосов реплики собеседников в живой ленте подписываются
именами автоматически (`--no-voices` отключает).

## Кнопка записи (трей)

Запись без Claude: ярлык запускает `meet-tray` — в трее появляется синяя
иконка (наведение — сколько идёт запись), правый клик → «Остановить запись»
→ уведомление с папкой записи. Повторный запуск при идущей записи просто
сообщит «Запись уже идёт». Если рядом дежурит резидент (см. следующий раздел),
новая иконка не появляется — команду выполняет уже висящая, меняя цвет с серого
на синий.

Создать ярлык на рабочем столе (из корня репозитория, powershell):

    $root = (Get-Location).Path
    $s = (New-Object -ComObject WScript.Shell).CreateShortcut("$env:USERPROFILE\Desktop\Запись встречи.lnk")
    $s.TargetPath = "$root\.venv\Scripts\meet-tray.exe"
    $s.WorkingDirectory = $root
    $s.Save()

На ноутбуке: `git pull`, `.venv/Scripts/pip install -e .` (подтянет pystray
и pycaw), затем та же команда ярлыка.

## Автозапись встреч Диона

`meet-tray --watch` дежурит в трее с серой иконкой и сам поднимает запись,
когда начинается звонок в Дионе; иконка становится синей с секундомером.
Через `grace_minutes` (по умолчанию 10 минут, от 1 до 60) после выхода из
конференции запись останавливается — ожидание нужно, чтобы обрыв связи и
перезаход в комнату не рвали файл надвое. Прежний ключ `grace_seconds` больше
не читается: 10 минут действуют и для старых конфигов. Минуты ожидания в
конце автозаписи потом обрезаются: резидент пишет в `events.jsonl` момент, когда
пропал сигнал звонка (`record.call_end`), и до расшифровки укорачивает дорожки
до конца сигнала + 30 с: разговор в комнате во время ожидания не сохраняется
(если звонок возобновился, обрезается только хвост после последнего его конца).
Пока идёт обрезка, запись помечена «Обработка». Если резидент закрыли раньше,
он доделает обрезку (и поставленные расшифровки) при следующем запуске.
Запись, начатую ярлыком или пунктом меню, детектор не останавливает: писать
можно не только конференцию.

Меню на записи: «Остановить запись» (сохранить) и «Отменить (удалить)» —
второе стирает папку и не зовёт Claude, если автозапись поймала лишнее.

`meet-tray --headless [--parent-pid N]` — тот же дежурный без иконки, для
оболочки приложения (control API, автозапись и lock-протокол прежние); с
`--parent-pid` завершается вместе с процессом N, а если дежурный уже запущен —
выходит с кодом 3.

Включается секцией в `%LOCALAPPDATA%/meet/config.json`:

    {
      "post_record_hook": true,
      "auto_record": {
        "enabled": true,
        "processes": ["Dion.exe"],
        "grace_minutes": 10,
        "poll_seconds": 2
      }
    }

`post_record_hook` открывает после записи окно Claude Code с предложением
транскрибировать — на машине без GPU его выключают: запись просто копится в
`recordings/` и разбирается там, где есть чем.

Детектор считает, что звонок идёт, если Дион занял микрофон **или**
воспроизводит звук (второй признак нужен против мьюта).

Звонки в браузере: `auto_record.browsers` (например `["chrome.exe"]`, по
умолчанию пусто). Для браузера звонок начинает только микрофон, занятый дольше
15 секунд подряд: видео, музыка, голосовой поиск запись не запускают. Начавшийся
звонок продолжается, пока браузер держит микрофон или воспроизводит звук
(веб-клиент на мьюте может отпустить микрофон) — видео сразу после звонка в том
же браузере тоже продлевает запись. `browser_require_site: true` вдобавок требует,
чтобы в заголовке окна браузера был сайт звонка из `call_sites` («Dion»,
«Google Meet», «Телемост»…, без учёта регистра); по этому же заголовку запись
получает начальное название («Dion — Планёрка»). Окна перечисляются только
пока браузер держит микрофон.

Всё, что он видит и
решает, пишется в `%LOCALAPPDATA%/meet/watch.log` — независимо от `enabled`,
так что за сигналами можно понаблюдать, не давая трею трогать запись.

Поставить дежурного в автозагрузку (из корня репозитория, powershell):

    $root = (Get-Location).Path
    $s = (New-Object -ComObject WScript.Shell).CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\Дежурный записи встреч.lnk")
    $s.TargetPath = "$root\.venv\Scripts\meet-tray.exe"
    $s.Arguments = "--watch"
    $s.WorkingDirectory = $root
    $s.Save()

## Приложение: плавающая панель

Поверх резидента живёт оболочка (`app/`, Tauri + React): компактная панель поверх
всех окон — состояние звонка, таймер, уровни двух дорожек, кнопки «остановить» и
«отменить», ход расшифровки, — и отдельное окно настроек с диагностикой.

    cd app && npm install && npm run app

Панель находит резидента по `%LOCALAPPDATA%/meet/daemon.json` и говорит с ним по
локальному control API (`meet status` печатает то же самое в консоль). Резидента
нет — панель предложит его запустить. Своей логики записи у оболочки нет: пишет
и владеет файлами по-прежнему резидент, поэтому старые сценарии (ярлык, трей,
CLI, автозапись) продолжают работать без изменений.

Подробности и dev-режим без Tauri — `app/README.md`; замысел целиком —
`docs/2026-08-17-desktop-app-architecture-plan.md`.

## Установка из исходников

    py -3.12 -m venv .venv
    source .venv/Scripts/activate
    pip install torch --index-url https://download.pytorch.org/whl/cu128
    pip install -r requirements.txt
    pip install -e .

Также нужны: ffmpeg (`winget install Gyan.FFmpeg`) и токен HuggingFace
(принять условия модели на hf.co: pyannote/speaker-diarization-community-1).
Токен задаётся в окне приложения и хранится в диспетчере учётных данных
Windows; переменная `HF_TOKEN` тоже работает. Без токена расшифровка идёт, но
без разделения на спикеров: «Собеседник» и «Вы».

Если в консоли кракозябры вместо русского — выполнить `set PYTHONUTF8=1`
(или `setx PYTHONUTF8 1`), на сам транскрипт это не влияет.

## Запись на другой машине

Запись не требует ни GPU, ни токена, ни ffmpeg — на ноутбуке достаточно
минимальной установки:

    py -3.12 -m venv .venv
    .venv\Scripts\pip install pyaudiowpatch
    .venv\Scripts\pip install -e .
    .venv\Scripts\meet record

Потом перенести папку `recordings/<дата_время>/` на машину с GPU и там
запустить `meet transcribe recordings/<папка>`. Файлы `sys.opus` и `mic.opus`
внутри не переименовывать. Запись сжата в Ogg/Opus 16 кГц моно — порядка
25 МБ на час встречи. Звук встречи должен играть через устройство вывода ноутбука
(наушники/динамики) — loopback пишет именно его.

Подробности: docs/superpowers/specs/2026-06-12-transcriber-design.md
